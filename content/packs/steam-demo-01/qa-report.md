# steam-demo-01 QA Report

## Pack Spine

四通来电都围绕“好听的身份或关系词，最后让谁承担钱和责任”展开。第一通是体面消费和债务，第二通是自己人话术和办卡，第三通是条件标签和资料缺口，第四通是主责、流程和垫付款。

## Required Checks

- 每案必须有一个具体物件：账单、店表、资料图、审批截图。
- 每案必须写出来电人自己的不利信息，不能只写对方有问题。
- 案间页标题使用物件钩子，不使用“下一案 / 下一通来电”当标题。
- 结果页不能写成教程、评分表或最佳答案解析。
- 当前试玩包的 manifest 已经通过 `npm run content:index` 生成运行时索引，`src/storyPacks.js` 不再手写一份包定义。
- 生成索引同时输出 `CONTENT_CASES`；四案均已切到 `runtime-loaded`，完整台词、追问、材料判定和复盘文案由内容包接管。
- `truthBoundary` 已随运行时内容进入 brief，后续结案对照和“今晚定不了”的收麦句可以直接读取。
- 新增案件时，运行时内容和 `content/packs/steam-demo-01/` 必须同步更新；如果 case JSON 没切到 `runtime-loaded`，只能保留策划压力包，不能夹带运行时台词字段。
- 结算、满格深问和剧本文档要按当前 caller/respondent 指派检查代词；角色可能换人时，用“咨询者 / 同事 / 对方”。
- 最终“选一句往下追”的引语必须来自无门控表面文本：开场、`sceneVersions[].version`、材料板或回流材料。不得只出现在某条分支回答里。

## Per-Case QA

| Case | Logic Chain | Caller Edit | Value Boundary | Fact Boundary |
| --- | --- | --- | --- | --- |
| 01-credit | 先出失业和体面消费，再让 1.2 万短视频分期改写“都是他安排”的说法，最后分开算他的递账和她的剪辑。 | 来电人把两个人经营的体面说成对方单方安排，也把自己受益的分期说成没细看。 | 批评隐瞒失业、造急和转嫁债务；同时点出来电人的剪辑，但不写成“她活该”。 | 能确认失业、账单压力和分期受益账号，不能确认失业前旧债来源或双方后续关系。 |
| 02-tony | 先听专属话术，再看排班/办卡，中段用“店里确实教话术”撑住假解，回流再用“下一次推进”私加列击穿它。 | 来电人吃了“自己人”的位置，也收过免费剪发、插号和顺手带客的好处。 | 批评复制暧昧话术换业绩，不把服务行业或性别当原因；好处不等于欠他投店。 | 能确认话术、推进表和商业路径，不能确认真实好感或其他顾客如何理解关系。 |
| 03-profile | 先看条件标签，再拆学历/流水，回流让玩家抓到“流水是她先开的口”，最后问婚后钱怎么管。 | 来电人说查真假，也是在筛婚后财务控制权；“我妈想看”里藏了自己的起头。 | 批评包装学历收入和借资料筛人，不把择偶标准本身当罪；节俭和收入缺口分开记。 | 能确认标签被修剪、流水起头和工资管理预设，不能确认全部资产和可支配收入。 |
| 04-workplace | 先看审批截图，再用财务延后真通知撑住假解，随后用供应商返款不走财务完成覆盖反转，最后落到主责机会和垫款风险。 | 来电人开场就承认想拿主责，终案从“藏了什么”翻成“自认好处是否等于认账”。 | 批评流程私下化和转嫁垫款，不把职场争取机会写成原罪；自认想表现不等于认下垫款。 | 能确认审批不等于付款、财务延后只盖住报销路，不能确认钱最终进谁账户或老板知情程度。 |

## Voice QA

- 直播中不显示路线轴、正确答案、最佳答案或教程提示。
- 主播问题必须基于屏幕上已经说过的事实。
- 外围选项也要像真实主播会问的话，不能是故意错选。
- 满格深问只问来电人自己的利益、面子、经济位置或隐藏诉求，不写成系统奖励。
- 结果页可以有余味和评论区争论，不能替玩家上价值课。
