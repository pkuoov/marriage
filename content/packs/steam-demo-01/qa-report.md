# steam-demo-01 QA Report

## Pack Spine

四通来电都围绕“好听的身份或关系词，最后让谁承担钱和责任”展开。第一通是体面消费和债务，第二通是自己人话术和办卡，第三通是条件标签和资料缺口，第四通是主责、流程和垫付款。

## Required Checks

- 每案必须有一个具体物件：账单、店表、资料图、审批截图。
- 每案必须写出来电人自己的不利信息，不能只写对方有问题。
- 案间页标题使用物件钩子，不使用“下一案 / 下一通来电”当标题。
- 结果页不能写成教程、评分表或最佳答案解析。
- 当前试玩包的 manifest 已经通过 `npm run content:index` 生成运行时索引，`src/storyPacks.js` 不再手写一份包定义。
- 生成索引同时输出 `CONTENT_CASES`；四案均已切到 `runtime-loaded`，完整台词、追问、材料判定和复盘文案由内容包接管。
- `truthBoundary` 已随运行时内容进入 brief，后续结案对照和“今晚定不了”的收麦句可以直接读取。
- 新增案件时，运行时内容和 `content/packs/steam-demo-01/` 必须同步更新；如果 case JSON 没切到 `runtime-loaded`，只能保留策划压力包，不能夹带运行时台词字段。
- 结算、满格深问和剧本文档要按当前 caller/respondent 指派检查代词；角色可能换人时，用“咨询者 / 同事 / 对方”。

## Per-Case QA

| Case | Logic Chain | Caller Edit | Value Boundary | Fact Boundary |
| --- | --- | --- | --- | --- |
| 01-credit | 先出体面消费，再出失业时间，最后用账单缺口落到谁承担最低还款。 | 来电人也被体面吸引过，不只是被催债。 | 批评隐瞒失业和转嫁债务，不批评失业本身。 | 能确认失业和账单压力，不能确认一开始是否蓄意骗钱。 |
| 02-tony | 先听专属话术，再看排班/办卡，再落到自己人身份被谁使用。 | 来电人也吃了自己人的情绪位置。 | 批评复制暧昧话术换业绩，不把服务行业或性别当原因。 | 能确认话术和业绩路径，不能确认真实好感。 |
| 03-profile | 先看条件标签，再拆学历/流水，再问婚后钱怎么管。 | 来电人说查真假，也是在筛婚后财务控制权。 | 批评包装学历收入和借资料筛人，不把择偶标准本身当罪。 | 能确认标签被修剪，不能确认全部资产和可支配收入。 |
| 04-workplace | 先看审批截图，再追付款状态和对接入口，最后落到主责机会和垫款风险。 | 来电人也想拿主责机会，所以先垫了。 | 批评流程私下化和转嫁垫款，不把职场争取机会写成原罪。 | 能确认审批不等于付款，不能确认财务最后打给谁。 |

## Voice QA

- 直播中不显示路线轴、正确答案、最佳答案或教程提示。
- 主播问题必须基于屏幕上已经说过的事实。
- 外围选项也要像真实主播会问的话，不能是故意错选。
- 满格深问只问来电人自己的利益、面子、经济位置或隐藏诉求，不写成系统奖励。
- 结果页可以有余味和评论区争论，不能替玩家上价值课。
