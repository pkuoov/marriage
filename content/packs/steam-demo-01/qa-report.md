# steam-demo-01 QA Report

## Pack Spine

四通来电都围绕“好听的身份或关系词，最后让谁承担钱和责任”展开。第一通是体面消费和债务，第二通是自己人话术和办卡，第三通是条件标签和资料缺口，第四通是主责、流程和垫付款。

## Required Checks

- 每案必须有一个具体物件：账单、店表、资料图、审批截图。
- 每案必须写出来电人自己的不利信息，不能只写对方有问题。
- 案间页标题使用物件钩子，不使用“下一案 / 下一通来电”当标题。
- 结果页不能写成教程、评分表或最佳答案解析。
- 当前试玩包的 manifest 已经通过 `npm run content:index` 生成运行时索引，`src/storyPacks.js` 不再手写一份包定义。
- 生成索引同时输出 `CONTENT_CASES`；四案均已切到 `runtime-loaded`，完整台词、追问、材料判定和复盘文案由内容包接管。
- `truthBoundary` 已随运行时内容进入 brief，后续结案对照和“今晚定不了”的收麦句可以直接读取。
- 新增案件时，运行时内容和 `content/packs/steam-demo-01/` 必须同步更新；如果 case JSON 没切到 `runtime-loaded`，只能保留策划压力包，不能夹带运行时台词字段。
- 结算、满格深问和剧本文档要按当前 caller/respondent 指派检查代词；角色可能换人时，用“咨询者 / 同事 / 对方”。
- 最终“选一句往下追”的引语必须来自无门控表面文本：开场、`sceneVersions[].version`、材料板或回流材料。不得只出现在某条分支回答里。

## Expansion QA

- 闲聊层共 40 条，分布在四案二十个场景；只补人物、习惯和情绪位置，不新增承重事实、金额、日期或第三方。
- 案 1 证言更新只重述已披露事实：“我自己挑的”锚在场景 4 正文“店是我用会员号订的”；“没敢细看”锚在场景 3 核心回答“我要说完全没心动，是假话”。
- 案 1 的找不同点是“他安排的那种店 → 我自己挑的”“没细看 → 没敢细看”；UI 不标注差异，让玩家自己听出来。
- 顾问铁线按效力层执行：赵律师只说垫付留痕和欠条，周会计只说审批、付款、到账三张纸；顾问文案禁用“圈 / 那一栏 / 哪一块”等侦查点位词。
- 案 2 对方留言的可抓剪辑是“这两码事”：他试图把表格里的办卡带客和亲密位置重新拆开，但案内已揭示的表格耦合正是“自己人”话术接商业目标。
- 案 4 对方留言的可抓剪辑也是“两码事”：他用财务节奏盖住审批路，用老规矩盖住供应商返款路，但案内已揭示这两条钱路都压在他手里。
- 案 4 账本备档候选转折：延后通知发布日 vs 他首次引用日。本批只登记，不实施。

## Narrative Guards

- **戏剧特许额度台账**：案 1=lurker，案 2=分裂，案 3=韵脚，案 4=一词两义；四案额度已满。后续任何新增戏剧性特许必须先撤旧项，不得叠加。
- **8 号收窄阶梯**：收窄天花板上移至流水本身:'王**'半姓与'三个王'应答可见;付款人指认仍永不可能;'尾号 3301 是谁'入有形未知清单,与'三个王'并列为案 1 双刃。委托线'不是工资'表述废止(行内可见),周会计回单改为备注空白解读。
- **"老规矩"设计性歧义备案**：领导批注中的"流程按老规矩补齐"与供应商的"返点老规矩"构成一词两义，属设计性歧义。任何表面（弹幕、顾问、回拨、终局、分享卡）不得替玩家解决该词归属；有形未知「"老规矩"从哪年开始、还有谁拿过」与之绑定。
- **设计性韵脚**：同一排靠窗位既演纪念日的体面也演相亲的体面，且介绍人拿得到位子——舞台是同一个。守则：**正片内任何表面不得点破两案关联**，只有终局墙这一句；两处植入细节（靠窗、提前两周）必须逐字保持可对上。
- **关系披露阶梯**：骂了一年、第七次道歉、第八次改饭——只存在于圣经；正片与终局至多露到"赵姐"级别的半知半觉；任何表面不得解释赵律师为什么总在。
- **家常配额**：每案家人/情侣梗至多一次；家常腔永不进入委托回单与顾问信的专业核心段。
