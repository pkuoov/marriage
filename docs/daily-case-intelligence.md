# 案件包情报台

## 目标

主模式已经从“每日一案”升级为“章节式案件包”。情报台的目标不再是每天产出一个孤立短案，而是先服务 Steam demo 案件包：

```text
一个故事集主题
若干个互相照应的公共生活事件
每案一通匿名来电
每案 5-6 个关键来电段，至少 20 分钟玩法
本集路线图和评论区审判墙
```

`daily` 仍然是代码里的单案内容单元和兼容入口；现有脚本名里带 `daily` 是历史命名，正式内容生产按 story pack 组织。

## 案件包硬规则

每个案件包必须遵守：

- 当前 demo 包是四案，约八十到一百分钟；后续案件包按主题和节奏决定案数，不固定四案。
- 包内案件围绕同一主题，例如钱流、材料缺口、身份标签、双方互害、流程入口。
- 案件不能只是随机拼盘；每案要在主题上推进、反问或换场景验证。
- 每案至少 5 个关键来电段，包含材料出现、利益转向、来电人自我修剪、第三方压力和责任落点。
- 每案保持单人匿名连线：直播间只有主播和咨询者，另一方只能通过转述、截图、录音、合同、账单、回拨内容或第三方匿名留言出现。
- 每个关键节点只能问一个选项。问完以后进入下一段咨询者陈述，不能扫同节点剩余选项。
- 常规咨询优先按一问一答控制信息量；进入反驳或对质后不设固定来回数，按否认、追问和改口逐句拆屏，每一拍都必须推进事实或人物防御。
- 满格路线才出现一个无选择的 `deepFollowup` 深问；非满格路线直接进入最终挑句。
- 每个选项必须带路线轴，例如来电人可信度线、材料缺口线、钱流结构线、流程入口线。
- 故事集收麦必须展示本集主题、每案路线、平均揭示率、主播倾向和评论区审判墙。

## 价值观与现实感

不靠性别对立，不做群体攻击，不把婚恋案写成男女互骂。

但现实里很多事件确实是双方互害。情报台不能因为“价值观要正”就把真实复杂性磨平。所有双方互害素材都要拆成行为链条：

```text
A 怎样修剪事实？
B 怎样修剪事实？
谁先启动失衡？
谁借善意、身份、家庭、平台或制度扩大伤害？
谁承担实际成本？
谁把自己的利益包装成道德要求？
```

合格素材不是“谁更坏”的标签，而是能让玩家问出“这句为什么没落地”的具体事件结构。

## 素材采集

每次准备新故事集时，从公开内容里抽象 10-20 张素材卡，来源可以是婚姻家事律师、情感博主、相亲博主、职场博主、消费维权博主、反诈博主、房产/保险/信托科普号的视频或文章。

不要搬运真实人物、账号、完整案情或原话。每张卡只保留可复用结构：

- 冲突类型：共同还贷、彩礼返还、赠与还是借贷、职场报销、消费退款、平台交易、租房押金、合租责任、熟人周转。
- 新话术：安全感、诚意、不信任、正常夫妻不会算这么细、流程已经过了、平台规则就是这样、我只是帮忙。
- 戏剧物件：截图、流水、账单、合同、审批页、排班表、报价单、录音、聊天原话。
- 互害结构：谁先试探，谁补刀，谁借别人之口，谁把成本推给对方。
- 可玩问题：玩家第一轮应该问时间线、钱、材料边缘、身份标签、流程入口、平台规则，还是来电人自己的利益。

## 热点融合原则

故事不是“一个热点改一个案”。标准做法是：

```text
3-4 张近期热点素材卡
-> 抽出主冲突、话术、材料形态、误读风险、第三方压力
-> 编剧重组为一个原创案件
-> 再拆成一通匿名直播来电
```

一案通常这样融合：

- 主热点给案件骨架，例如共同还贷、报销返款、资料包装。
- 第二个热点给话术，例如“安全感”“一家人”“流程已经过了”。
- 第三个热点给材料形态，例如截图缺边、流水少页、合同照片、审批页。
- 第四个热点给误读风险或第三方压力，例如父母、平台、中介、老板、朋友。

融合后必须做到：

- 换人物关系，不保留原热点里的身份组合。
- 换材料触发，不照搬原视频/文章里的证据出现方式。
- 换金额、时间线、地点和推进顺序。
- 保留现实争议结构，但不能让玩家或观众反推出单一真实事件。
- 每个被融合的热点只能贡献一个结构功能，不能几个热点一起堆成新闻摘要。

## 本地工具

仓库提供轻量采集脚本：

```bash
npm run intel:collect
npm run intel:drafts
npm run intel:creator-template
```

默认读取：

```text
docs/daily-intelligence-sources.example.json
docs/daily-intelligence-creators.example.json
```

默认输出到：

```text
.local/daily-intelligence/<YYYY-WW>.json
```

`.local/` 不进入版本库，适合放真实链接、素材摘录和内部审核稿。正式入库时，只把抽象后的玩法结构改写进模板或未来的 `content/packs/<pack-id>/` 数据包，不直接复制视频标题、人物、原话和完整案情。

## 故事集素材包格式

```text
storyKey:
steam-demo-01

theme:
截图是真的，意思可能是剪过的。

themeThesis:
材料不一定假，但被截掉的边、没露出的账户和没说完的上下文，才决定它想让谁闭嘴。

case 1 / 热场案:
20 分钟左右。钩子强，最好一个物件能立刻让评论区吵起来，但仍要完整五段来电。

case 2 / 主案:
25-30 分钟。互害、钱流、材料缺口、身份包装要更深。

case 3 / 反问案:
20 分钟左右。换题材或换关系，反照本集主题，不能降级成短尾彩蛋。

case 4 / 落点案:
20 分钟左右。离开前面最容易被情绪带跑的场景，把同一主题落到公共生活或流程入口。

commentWallSeed:
本集评论区最该吵的一句话。
```

## 单案入库格式

```text
热点钩子：
报销截图都发了，钱为什么还没回来？

压力系统：
谁想保全面子，谁想推进下一步，谁承担实际成本。

戏剧物件：
报销审批截图、项目署名群聊、供应商报价单。

材料用途：
截图想让咨询者停止追问；署名想让咨询者接受垫款风险；报价单暴露返款入口。

关键节点：
第一段问垫款和署名 -> 暴露机会和资金风险绑定。
第二段问审批截图边缘 -> 暴露审批不等于付款。
第三段问供应商返款 -> 暴露入口控制。

满格深问：
如果不只是钱没回来，你最怕公司里怎么说你？

结论画像：
钱流雷达 / 截图拆边 / 来电人可信度 / 外围试探。
```

## 编剧 Agent 生成策略

每案不允许按字段拼装，也不允许“发现一句怪就只改一句”。必须先一体化生成整通电话，再拆成代码字段。

生成采用 writers-room 多角色流程：

1. Hotspot Curator Agent：把近期网络热点拆成素材卡，只保留结构，不保留原案。
2. Showrunner Agent：把 3-4 张热点卡融合成一个原创案件，再写本集主题、四案组合、价值边界和最终评论区争点。
3. Case Writer Agent：先写 ending-first argument，再写压力系统。
4. Beat Ladder Agent：为每案写 5-6 段来电，分别承担表层不对劲、材料缺边、利益路径、来电人自我修剪、责任落点。
5. Branch Designer Agent：每段写 2-3 个主播追问，分清核心揭示、外围试探和路线轴。
6. Actor Consistency Agent：分别站在咨询者、对方、第三方压力位置，检查每句话保护了谁的面子、钱、责任或退路。
7. Continuity QA Agent：串读 opening、5-6 段来电、deepFollowup、最终原话、复盘和评论墙，查跳步、提前剧透和未披露事实。

拆字段顺序固定：

1. 先给每案选 3-4 张热点卡，并写 `hotspotFusion`：主冲突、旁支话术、材料形态、误读风险。
2. 写本集主题。
3. 为四案分别写最终评论区争点和压力系统。
4. 确认四案之间的互相照应：同主题、不同场景、不同伤害方式。
5. 写每案 5-6 段 stitched transcript。
6. 拆字段：`openingDialogue`、`sceneVersions`、`questionOptions`、`deepFollowup`、`evidenceCards`、`accusationChoices`、`stageJudgement`、`truth`、`share`。
7. 给每个 `questionOptions` 标路线轴和语气倾向。
8. 写本集评论墙种子。
9. 串读全案，确认主播没有提前知道答案，也没有还原任何单一真实热点。

评分低于 10 分不得入库。评分项包括结构、冲突、角色、互动、回收、现实感、价值观；任一项 0 分必须重写。

## 玩法原则

- 同一个 `storyKey` 生成同一个案件包；旧 `weeklyKey` 只做兼容。
- 同集不同玩家可以走出不同路线图。
- 玩家不是“答题”，而是在决定怎么理解一句话。
- 每案优先做争议判断题，不做完整法条教学。
- 单案不做双边对质，所有可玩信息必须从咨询者当前能说、能念、能拿出的材料里披露。
- 结算卡先表达玩家判断画像，再给事实复盘。
- 反制方式必须允许被正确使用、被曲解、或被滥用，不能默认“懂法律的一方一定正确”。

## 入库前检查

每个故事集入库前必须确认：

- 是否有性别对立或群体攻击。
- 是否把双方互害写成了含糊端水。
- 是否有至少一个足够戏剧化的物件或原话。
- 材料是否有出现目的。
- 主播每个问题是否只基于已出现信息。
- 非核心选项是否仍然有人会点。
- 满格深问是否揭示来电人的利益、面子、成本或隐藏诉求。
- 本集主题是否在四案中都有回声。
- 评论区审判墙是否来自玩家路线，而不是固定宣传语。
