# 每日案件情报台

## 目标

每日模式只发布一个公共 case。玩家看到同一个开头，但因为三轮询问路线不同，会拿到不同证据、形成不同判断画像，并把结果分享给朋友挑战同题。

每日案不追求长篇回溯，而是模拟短视频、直播连线和律师科普里的线性对话：先听第一版说法，再用有限追问判断该把问题压回时间线、钱和资源、情绪话术，还是资产边界。

## 每日关卡硬规则

以后所有每日关卡都必须遵守“单人匿名连线”：

- 直播间只有主播和一个匿名咨询者，不出现真名，不让另一方直接上麦。
- 所有 `sceneVersions` 和 `testimony` 都必须由咨询者讲出。
- 对方只能通过咨询者转述、聊天截图、录音、合同、账单、回拨内容或第三方匿名留言出现。
- 材料不能自己成为说话人。不要写“后台账单”“回拨新情况”“主播记事”直接插入流程，要写成“我把账单翻出来”“我手里有合同照片”“我把他后来那句回复念一下”。
- 主播通过追问一个人的叙述发现漏洞，不做两边对质、不做庭审式调解。
- 咨询者也不是完全可靠叙述者。TA 可能保护面子、淡化自己责任、害怕承认看走眼、或为了保住关系而漏说关键前提。

## 每周采集

每周从公开内容里抽象 5-10 张素材卡，来源可以是婚姻家事律师、情感博主、相亲博主、反诈博主、房产/保险/信托科普号的视频或文章。

不要搬运真实人物、账号、完整案情或原话。只保留可复用结构：

- 冲突类型：洗房、加名、共同还贷、彩礼返还、婚前协议、赠与还是借贷、信托/保险安排。
- 新话术：安全感、诚意、不信任、正常夫妻不会算这么细、我爸妈只是帮忙。
- 反制方式：份额登记、资金流水、赠与声明、借条、公证、婚前协议、资产隔离。
- 误读风险：合理保护被曲解成算计，真实算计被包装成保护。
- 可玩问题：玩家第一轮应该问时间线、钱、产权、家庭角色，还是情绪动机。

## 本地工具

仓库提供了一个轻量采集脚本：

```bash
npm run intel:collect
```

默认读取：

```text
docs/daily-intelligence-sources.example.json
```

默认输出到：

```text
.local/daily-intelligence/<YYYY-WW>.json
```

`.local/` 不进入版本库，适合放真实链接、每周摘录和内部审核稿。正式入库时，只把抽象后的玩法结构改写进每日 case 模板，不直接复制视频标题、人物、原话和完整案情。

配置源支持三类：

- `manual`：手工录入标题、链接、发布时间和短摘要，最稳，适合中文短视频平台。
- `rss`：读取公开 RSS / Atom。
- `page`：读取单个网页标题和 description。
- `bing-news` / `bing-web`：用公开搜索 RSS 尝试抓取热点，适合律师新闻和公开网页，不适合依赖平台内分发的视频账号。

## 账号热点观察

像鳌烨、天书、陈楠、大超说媒、杰哥相亲，以及各类律师号，最适合做“每周观察清单”。但它们很多内容在抖音、小红书、视频号等平台内，通用搜索经常抓不到，或者抓到天气、字典、无关页面。

所以实际流程应是：

1. 每周生成账号人工摘录模板：

```bash
npm run intel:creator-template
```

默认输出：

```text
.local/daily-intelligence/creator-manual-source-<YYYY-WW>.json
```

2. 人工看一轮重点账号。每个账号只摘 1-3 条“新套路 / 新话术 / 新方法论”，填入模板里的 `items`。未使用的 `待填写` 占位条目可以保留，采集脚本会自动跳过。

3. 用人工摘录模板生成素材卡和每日案草稿：

```bash
npm run intel:collect -- --config .local/daily-intelligence/creator-manual-source-<YYYY-WW>.json --out .local/daily-intelligence/creator-cards-<YYYY-WW>.json
npm run intel:drafts -- --input .local/daily-intelligence/creator-cards-<YYYY-WW>.json --out .local/daily-intelligence/creator-drafts-<YYYY-WW>.json
```

4. 人工审核草稿，再决定是否转写进 `src/caseEngine.js` 的每日模板。

已提供账号观察配置：

```text
docs/daily-intelligence-creators.example.json
```

它同时包含公开搜索源和人工摘录兜底。采集脚本会把明显噪声放进 `rejectedCards`，不会进入每日案草稿。

示例：

```json
{
  "label": "婚姻家事律师手工摘录",
  "type": "manual",
  "kind": "lawyer-video",
  "tags": ["婚前协议", "房产"],
  "items": [
    {
      "title": "婚前房写父母名下，婚后共同还贷要不要写清份额",
      "url": "https://example.com/lawyer/house-boundary",
      "publishedAt": "2026-06-21",
      "snippet": "房本、首付、共同账户还贷、装修款、退出补偿。"
    }
  ]
}
```

## 入库格式

```text
热点钩子：
婚前房写父母名下，却要求婚后共同还贷。

第一版叙事：
咨询者说：TA 说写协议就是不信任。

核心分歧：
合理资产隔离 vs 只隔离产权、不隔离现金流的洗房风险。

材料出现原因：
咨询者为什么会拿到账单/合同/截图/录音？这份材料当时想证明什么、说服谁？

三条询问路线：
问房本 -> 咨询者翻出合同照片，获得登记信息。
问流水 -> 咨询者补充共同账户计划，获得还贷缺口。
问情绪 -> 咨询者复述“不信任”话术，但可能漏掉权属问题。

结论画像：
资产边界型侦探 / 同情心先行型 / 过早站队型。
```

## 编剧 Agent 生成策略

每日案不允许按字段拼装，也不允许“发现一句怪就只改一句”。编剧 agent 必须先一体化生成整通电话，再拆成代码字段。

生成顺序固定为：

1. 先写“压力系统”：
   - 关系阶段：为什么今天打来。
   - 压力点：父母、钱、面子、时间、平台、前任、朋友或家庭角色如何把事情推到台面上。
   - 戏剧物件：截图、存款证明、账单、协议、录音、表格、转账、原话。
   - 咨询者利益：TA 为什么这样讲，怕谁看低，怕哪里打脸，淡化了什么责任。
   - 对方利益：TA 为什么这样展示/隐瞒/转移话题，完整说出来会失去什么。
   - 第三方压力：父母、朋友、平台、中介或舆论是否参与推动。
   - 真实边界：哪些是真的，哪些是半截真的，哪些暂时无法确认。

2. 再写 stitched transcript：
   - `caller line -> host bridge -> caller reply`
   - `caller scene beat -> host options -> caller feedback`
   - `caller testimony -> host follow-up -> caller answer`

3. 最后拆字段：
   - `openingDialogue`
   - `sceneVersions`
   - `questionOptions`
   - `testimony`
   - `followups`
   - `evidenceCards`
   - `accusationChoices`
   - `stageJudgement / truth / share`

拆字段时必须遵守：

- 每个选项都要回到同一个压力系统，不能突然问“还喜不喜欢”“要不要相信”这种偏离核心的问题。
- 每句反馈都要回答刚才的问题，不允许引入没有桥接的新事实。
- 每句结论都要能在前文找到已披露事实支撑。
- 修改任意一句涉及动机、面子、证明用途、责任归属的文案时，必须重读并同步更新同一条链上的开场、选项、反馈、结尾和分享文案。

## 玩法原则

- 同一天所有玩家默认同题，分享链接携带 `dailyKey`，隔天打开也能复现同题。
- 同题不等于同结果。结论由玩家问到的证据、整理方式和最终指认共同决定。
- 每日案优先做争议判断题，不做完整法条教学。
- 每日案不做双边对质，所有可玩信息必须从咨询者当前能说、能念、能拿出的材料里披露。
- 结算卡先表达玩家判断画像，再给事实复盘。
- 反制方式必须允许被正确使用、被曲解、或被滥用，不能默认“懂法律的一方一定正确”。
