# 直播快案：主播对质模式

## 目标

把一通有所隐瞒的咨询压缩成十几分钟的完整小故事：玩家先听一段，再判断当前已经出现的问题方向；林旭阳当面追问以后，来电人的否认或改口会带出下一段。快案不设置圈具体句子、评分、弹幕补线或评论区裁判，冲突只发生在主播和来电人之间。

## 第一关：《什么都不图》

林旭阳直播之外也替登记过的单身听众做少量同城介绍。一位二十四岁的服装销售因此请他介绍对象。她先用工作、收入、名下小两居和父亲的经历证明自己能独立生活，随后把条件放到月薪四五千、没房、年龄大她五岁以内。主播给出符合条件的普通对象时，她不直接拒绝，而是用“不够了解”挡一下，再把安全标准加到主播熟悉、自己经商、家里稳定的男性。

原始连线共十七组问答，分两轮披露。第一轮先播十组，用工作、收入、房子和父亲经历立住“独立、要求低”的版本，只开放钱款来源与异常生育举例两个方向；问完以后，她的最小承认让对话进入择偶资源与背书诉求。第二轮再播七组，只开放实际筛选标准与分手原因两个方向。未来轮次的问题不会提前显示：

- 亲生父亲只能偶尔帮人看店，给她一百万元买房的“爸爸”究竟是不是同一个人。她先坚持“我一直叫他爸爸”，被主播逼着只回答是否亲生以后才承认不是，再用隐私和自愿赠与挡住真实关系。
- 她在讲相互扶持时偏偏拿自己不能生孩子举例；首轮主播不追。玩家选中这个疑点以后，她先反驳，主播短追一句，她才承认做过检查。
- 她口头接受月薪四五千、没有房的对象，也说不会让男方养她；实际又避开符合标准的普通上班族，指定主播熟悉的经商男性，还希望对方减轻总价两百万元房子的贷款压力。
- 她把一段关系散掉归因于不会讲好听话，求主播背书时却立刻恭维、改称呼并让他先替自己说好话；玩家追问的是这究竟是不是分手的根本原因。

每次对质只处理一处矛盾。来电人不完成自我审判：她先淡化、强调隐私，再替自己的双重标准找理由，最后因主播拒绝背书而不耐烦。反差来自她在普通问话里说得从容、被逐项问回时却不断改换理由。

林旭阳拒绝介绍并挂断以后，还要完成两段口头复盘。第一段把两个“爸爸”、口头低条件与实际筛选、不能生育例子的下意识泄露、临场软话重新放在一起。第二段给出目前最能解释它们的高概率经历：她成年后长期处在一段经济交换关系里，一百万元很可能来自这段关系，又想借主播信誉接触条件更好的对象。她长期称对方为“爸爸”，对方年龄明显更大；她主动拿自己不能生孩子举例，回问后又承认做过检查，说明问题确实落在她本人身上。主播只把这段关系是否仍在持续、她是否另有伴侣和检查结果的具体成因留在制作边界。

## 第二关：《那晚没回消息》

一位二十六岁的985高校在读硕士来问：自己通过婚恋机构认识了一位三十五岁的创业者，两个人相处一个月后，男方突然停止联系。介绍男方时，她先强调家里能支持自己、不是指望对方养，随后又报出男方至少中A8、本地两套平层，自己家为A7；这些资产分档只是她的自述，却让“条件合适”在开场就有了具体含义。她把问题先说成两个人缺少深度交流，又说真正的起点只是自己喝多以后漏回一条消息，想知道是不是男方把这件事看得太重。

这通电话分三轮。第一轮十七组问答先让“我只想被理解”的版本站住；她说明朋友圈现在三天可见，主播从外面看不到旧内容，再由她自己翻出花、包和车同框的那条动态及前几条并截屏发来。主播先从照片问出包也是男方送的，再从点赞、羡慕、她的回复，以及漂亮饭和演唱会问回她没有说出口的物质与展示需求，随后才从消息时间追到醉酒时仍回“还行”。第二轮只有三组追问：酒是谁点的、当晚是否只有姐妹两人；来电人先说“还有别人点的”，玩家追问后她才从“妹妹的朋友”改口到“一名男性朋友”。第三轮先追问男方为什么会知道桌上还有别人，来电人才承认自己解释时说漏一个“他”，被男方追问后才补充；随后她又从自己的朋友圈翻出近两个月带时间的动态，截屏发来想证明自己平时不这样。林旭阳只能查看她交来的截图，并从中看见六次酒吧、KTV 和凌晨五点十七分的照片；继续追问，她才承认读研以后聚会一直不少，同行的男男女女也不是固定一拨，其中两三次玩到天亮。她仍把这些压成普通聚会，没有在开场交代自己的真实生活状态。事实按对质逐层出现，而不是一次摆出答案：

- 她说自己只想要深度交流，最具体的相处事实却包括主动让男方送花、收下男方送的包，并把花、包和男方的车拍进公开动态。她发来的截图里，朋友点赞、说羡慕，她回复得很开心；前几条也多是漂亮饭和演唱会。主播可以据此判断她同样在意男方的物质条件，以及自己的生活如何被别人看见。
- 她把冲突说成没有看到一条消息。记录显示十一点五十二分她还回了“还行”，六分钟后不再回复；她后来承认，当时已经喝到难受，只是不想让男方知道自己喝多。
- 她先说跟妹妹小聚，谈到酒量时才补出桌上还有妹妹的一名男性朋友。男性在场不能自动证明越界；真正改变判断的是，她为何把三人混酒到断片缩成姐妹俩喝一点。
- 她第二天对男方也先只说妹妹送自己回去。解释时说漏一个“他”，男方问这个“他”是谁，她才把第三个人补上。
- 婚介跟男方说她生活简单，她也说自己很久没出去；后来才承认八号与师姐去 KTV，九号又去酒吧，连续两晚外出。近两个月的截图出现六次夜场，继续问，她又承认读研以后聚会一直不少，同行有不同圈子的男女，其中两三次玩到天亮。她到这时仍把长期状态说成普通聚会。
- 她说十号醒来后一直认真解释和道歉，同一天却仍公开发出八号 KTV 的照片。动态只显示十号发出，男方并不知道照片拍于八号；她刚解释完九号为什么喝断片，转头又发喝酒照片，道歉自然显得乏力。

每轮只显示当时已有依据的方向；年龄差和创业者是否太忙可以暂时存疑，但不再拿“去酒吧本身是否错误”充当一个选项。第三轮的新增方向改为追问男方如何发现第三个人。最大反转仍落在“姐妹俩小聚”被追问出第三个人：主播先问，对方先含糊成“妹妹的朋友”，再被逼着承认是男性；承认出现后才播放一次重击过场，不能在问题刚选中时提前给答案。她肩臂上的大片纹身属于男方初见时已经知道的人物背景，不做玩家质证，也不能单独证明她的生活方式。

结案不靠猜测酒局中是否发生了其他事。主播可以直接判断：男方不是因六分钟没回复而退出，而是在连续两晚饮酒、男性同行者、喝到断片、道歉当天的动态和她分层补充事实的过程中，重新判断她是否适合长期关系。她想先留住一个条件好的供养者，同时不耽误自己继续出去玩；嘴里的“深度沟通”和“情绪价值”只是替自己找的借口。说白了就是骑驴找马。玩的心思都没消退，认真找结婚对象的人不会接受。

## 玩家流程

1. 从标题页进入“直播快案”，先看到案件选择页，不覆盖四幕主线进度。
2. 每宗快案只显示稳定的两位案件编号、标题与完成状态；已完成案件保留对勾，也可以重玩。预计时长不放在玩家界面。
3. 每宗按二至三轮逐页推进。第一关是十组问答后对质、再播七组；第二关是十七组问答后对质、三组改口追问后对质、再播九组材料追问。普通问话没有提示、圈句或实时评论。
4. 每轮局部问话结束后进入问题方向选择。按钮只写当前已有依据的疑点，不写主播答案句；后续轮次的方向保持隐藏。错误方向不会扣分，只在按钮上标成“目前接不上”，不追加解释，也不替玩家排除答案。
5. 每选中一个成立方向，林旭阳当面指出对应的前后矛盾，来电人否认、改口或作最小承认；本轮问完后，新的说法自然带出下一轮问话。
6. 最后一轮所有成立方向问完以后，由主播按本案求助作出决定，来电人作最后反应，通话结束。
7. 挂断后继续留在主播视角：先复盘已经成立的矛盾，再说出有完整推导链的高概率故事版本，最后说明哪些部分仍不能实锤。只有最后一页的最后一句显示后，案件选择页才打上完成对勾。

## 舞台呈现

- 整通快案固定在同一间直播间。林旭阳在左，当前来电人在右，背景不变；每宗快案使用自己的匿名像素立绘，不能串角。
- 原始连线、当面对质和最终收束都按逐句播放：两张立绘始终在同一直播间背景中，一屏只显示当前一方的台词；当前说话者提亮，另一方压暗，问句和回答各占一拍。
- 舞台层只显示人物姓名与当前状态。不得显示“第 X/Y 屏”“对质 X/Y”“本轮 X/Y”或完成比例；玩家通过来电人的改口和新问话感受推进。问题方向以同权重按钮出现，不用颜色、顺序或“正确”标签泄露答案。
- 案件入口遵守观众可知边界：只写“有人来电”和她表面上的求助，不用简介替玩家概括学历、职业、相识渠道、消费、失联导火索或自我归因。所有具体案情从接通后的第一句开始披露。
- 来电人立绘是玩家侧的戏剧化想象，不代表节目获得了摄像头画面；主播和证据系统不得从她的表情、衣着或背景推断事实。

## 内容与版权边界

本模式受用户提供的公开视频启发，使用“把同一来电人的公开陈述前后对照”这一互动结构。第一关的人物、金额、家庭经历、台词和结论均为原创虚构。第二关依据 `BV1iGKG65EJ3` 重新核对原视频的公开因果骨架，保留主动要花、收到男方送的包并发动态，连续两晚 KTV 与酒吧、男性同行者、混酒到断片、六分钟消息差和道歉当天再发旧照等承重节点；人物姓名、具体年龄、婚恋机构、聊天措辞、对质台词和舞台结论均重新创作，不复刻原句，也不把异性在场单独写成越界证据。

## 数据与代码

- 内容真源：`content/packs/steam-demo-01/quick-cases/*.json`
- 角色真源：`content/characters/cast.json`
- 纯状态机：`src/runtime/quickDetectiveModel.js`
- 纯界面模块：`src/ui/quickDetectiveView.js`
- 内容入口：`content/packs/steam-demo-01/manifest.json` 的 `quickCases`

案件选择顺序只读取 manifest 的 `quickCases`，不在界面里另写一份列表。每个快案必须提供唯一 `id` 和两位数字 `caseNumber`；编号属于内容身份，不随列表位置临时重排。完成记录独立保存在玩家存档中，重开主线或返回标题页都不会清除。

新增快案至少需要三项 `confrontations`，并用 `disclosureRounds` 分成二至三轮。每轮只开放一至两个成立方向，登记该轮话轮范围、允许显示的选项和必须完成的对质；未来方向不能提前出现。每项对质必须有唯一 `id`，并用 `basisTurnIds` 指向当前已经出现的原始话轮。若新事实由对质逼出，应写进 `answerAdds`，并只供后续轮次使用。反驳不限定一问一答：刚好两句的简单对质可以继续用 `host / caller`；需要否认、追问、改口或再次反驳时改用逐句 `lines`，按实际攻防交替排列，每句单独显示。`issueOptions` 为每项对质提供一个不含结论的玩家可见方向，并至少提供一个合理但尚不能互证的干扰方向；干扰方向不得携带系统讲解，点击后只标为“目前接不上”。每宗只能有一项 `revealTransition`，必须落在重新解释整案的最大反转上；若答案来自来电人的承认，用 `lineIndex` 把动画放在承认之后。当前段的必要对质完成后，流程必须直接接入下一段问话；恢复存档时若检测到当前段已经问清，也要自动续播，不能停在只剩已完成按钮的选择页。`summaryPages` 至少分为结束通话、矛盾复盘和高概率判断三段；高概率判断必须说明由哪些已播事实推来，也必须当面保留尚未证实的关系和身份。`confirmed / unknown` 继续约束结案边界，但不上屏替主播说话。
