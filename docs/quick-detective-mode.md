## 两种模式

来电案围绕当前争议集中问询，没问清就在本段重新问，问清后推进。实际问句由主播说出，来电人接话。唯一有效接话自动进入对白，只在问法有实际区别时显示选择。错问听完回应后本段再问，不扣耐心、不限次数。不得强制整段重听、循环拉回原句或收麦后补完成度，也不使用弹幕与听众评价作惩罚。

单人口播设置 `format: "solo-commentary"`：当前公开材料读完，玩家选一个有依据的点评，使用 `completionMode: "any"` 直接推进。不同有效角度不判错，不要求全点。没有当事人在线，不能凭空安排回应或招认。

两种模式都不设固定轮数和时长，不用显然无关的选项凑数。未提供的事实仍是未知，角色可以做有来源的推断，但材料与作者记录不认证猜测。

## 内容接入与存档

真源 `content/packs/steam-demo-01/quick-cases/*.json`，角色真源 `content/characters/cast.json`。状态机 `src/runtime/quickDetectiveModel.js`，界面 `src/ui/quickDetectiveView.js`。

- 案件提供唯一 `id` 与两位数字 `caseNumber`，顺序只读 manifest 的 `quickCases`。完成记录独立，不能因重开主线而清除。
- 按实际段落配置 `disclosureRounds`、`issueOptions`、`confrontations`；`sourceAnchor` 绑定当前已播原句，`basisTurnIds` 指向本段已读来源。标签说明发问或点评切口，不偷放结论。
- 普通交流可用 `autoConfrontationIds` 接入，不把人物自然谈到的事强制变成找错题。误问必须有实际 `question` 与回应，不能只有内部标签。
- 多入口共用对话时，开头要接得上被选原句，共用完成 ID 保持稳定。旧 `activeIssueId / missPhase / missPenaltyPending` 等进度迁移保持已播、未播和已完成状态；历史预算原值保留，现行误问不再结算费用，也不跳过未读交流。
- `ending.summaryPages` 是现有承载收束对白的字段，不要求总结页数量。可以简短结束；必要新问题放回相应段落。内部 `confirmed / unknown` 不上屏，不得把转述升格为确认。
- 口播读档已有本段任一完成项就继续下一段；最后真实收束完成后才写完成对勾。不能只置完成标志跳过正文。

## 舞台与验收

来电案显示主播与来电人，口播显示主播与公开材料。立绘是演出，不代表主播看到摄像头；入口不泄露案情。操作、原话、材料和回答有明确位置，不显示答对比例、关键答案标记或弹幕裁判。

按当前授权修改并验证受影响模式、来源先后、局部重问、直接推进、保存恢复和 PC 布局；源码审读与浏览器试玩分开报告。旧回放用例只用于兼容检查，不能据此恢复循环设计。
