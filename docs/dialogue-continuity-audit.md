# 对话连贯性审查

审查日期：2026-06-30

## 审查标准

按理发店案重写后的逻辑，所有案件对话都按这条线检查：

```text
开场只给事件钩子，不提前把答案说完。
每一段只新增一个信息。
玩家追问必须承接当前段，而不是凭空跳到结论。
关键材料要分层露出：先看到物件，再看到缺口，再看到用途。
来电人自己的隐藏诉求要放到后半段或满格深问，不放在第一屏。
复盘只能总结玩家已经听到过的事实。
主流程是剧情文本游戏，不是过关提示器；不能实时展示命中数、缺口答案或“应该先看什么”。
来电人只报告自己当时看到、听到和感到的事，不替玩家把推理结论说完。
防备收紧回答应该更少袒露，不能提前复用满格深问、结算或最终原话里的自白金句。
主案与快案的承重按钮只写疑点方向，不提前展示主播完整问句；点击后再由玩家角色把方向说成自然问话。
每案只允许一个案内核心反转过场，且必须由玩家选中对应方向后触发；普通命中、错误方向和自动播放都不闪。
```

方向标签和完整问句必须分开审。标签只点出当前已经看见的人、物、金额、时间或不一致，不得写成答案；完整问句仍要通过相邻话轮承接检查。核心过场只负责给最大反转留出半拍，不负责解释结论：保持短促、不可操作、无剧透文字，使用现有立绘的聚焦变化，并尊重系统的减少动态效果设置。

## 求助与重大隐瞒闭环（2026-08-05 新增）

每案先登记四件互不替代的事：来电人公开求助什么、为什么今晚打来、想保住什么利益，以及压下了哪件最影响建议的事实。公开求助只分两类：问“为什么／这意味着什么”，或请求一个决定、资源、关系结果及其他现实利益。

在这四项之外，必须再写一张“咨询获益账”：来电人已经得到什么、还想得到什么、不愿付出或交还什么，以及准备用哪套道德说法包装这个要求。利益不能只写成“情绪价值”“安全感”一类抽象词，至少落到金额、消费次数、客户人数、劳动、账户控制权或支付时点中的一项。案件可以分别采用三种发动机：逃避本应承担的成本、发现自己长期被利用，或把单边多拿包装成合理安排。

最终建议必须按事实分流，而不是用一句“双方都有问题”收场。已经正常履行的消费、不当使用姓名和联系方式、尚未发生的交易，应分别处理；提出高额财产条件、拒绝接受该条件、故意隐瞒现有材料范围，也应分别处理。重大隐瞒揭开后，如果建议的对象、范围和优先级都没有变化，说明获益发动机仍未真正接入剧情。

审查时把重大隐瞒公开，再重新回答最初的求助。如果主播仍会给出完全相同的建议，这个隐瞒只是人物纹理，不能承担案件核心。核心隐瞒必须在前段留下玩家可以发现的痕迹，并由追问、圈行、回放或带回材料揭开；来电人只能在被碰到后辩解或承认，不能靠主动自白替玩家交付反转。隐瞒可出于羞耻、恐惧、缺钱或保住关系，不自动证明人物恶意。

## 多层伪装链（2026-08-07 新增）

长篇案件里，来电人通常不会只漏说一次，再在结尾把真相完整讲出来。先固定作者事实和一个受保护的现实目的，再登记三到五层表面口径。口径可以是直接假话，也可以是省略受益人、缩小金额、改称礼物、转移主动者，或用一句真的话暗示一个假的整体。

每层必须回答八件事：什么压力逼出这句话、当下说了什么、删掉哪项事实、这句话现在能换来什么、此前哪里已经露出痕迹、玩家用什么动作检验、被问中后最少承认到哪一步、建议因此怎样变化。下一层只能在上一层被问窄后出现；如果一处新秘密与共同目的无关，或者放在任何场景都一样，它不是伪装链，只是另一条线索。

人物可以逻辑不完整，作者不能。人被问中时通常先承认最小部分，再替剩下的行为换一个说法；不要让来电人忽然用一段完整总结替玩家复盘自己的五次改口，也不要让主播像审计报告一样逐项念出来。案一、案二的作者账本写在 `deceptionChain`，`PACK-020` 同时检查玩家检验和可玩改口锚点，避免结构只存在于文档。

## 逐话轮承接审查（2026-07-20 新增）

过去的审查以整案信息顺序为主，能看出线索是否提前、反转是否成立，却容易漏掉一句问话凭空引用未必出现的分支答案。现在增加独立的相邻话轮审查：

- 每个问题登记上文抓词、问题抓词、回答落点和具体承接理由。
- 防备回答单独登记，不能只审正常回答。
- 可选补问按任意顺序检查，不能依赖玩家先问过某个兄弟选项。
- 场尾按所有关键选项检查，不能默认玩家命中核心答案。
- 不允许为了排剧情而拒答。来电人明知物件去向且被直接问到时，应说出事实并给出自己的辩解；只有羞耻、金钱、安全、身份或归责风险在当下听得见时，拒答才成立。后一幕应深化动作与责任，不能把同一个物件归属硬藏一夜再揭。
- 生活噪声、停顿和舞台动作之后，主播必须在字面上把话题接回来。
- 跨场只允许继续、重提旧线或被现场事件打断，不能靠作者知道下一场要讲什么。

真源是 `content/packs/steam-demo-01/dialogue-adjacency-review.json`，可读表由以下命令生成：

```bash
npm run content:adjacency-report
```

报告路径：`docs/generated/steam-demo-01-dialogue-adjacency-report.md`。已锁定案件的锚点缺失、问题数量变化、防备回答漏审或报告过期都会使 `npm run check` 失败。语义是否自然仍由人逐行确认，脚本只负责阻止审查结果与实际台词脱节。

四案现已全部完成逐话轮人工锁定。每次修改开场、固定场景、普通补问、关键追问、防备回答或场尾，都必须同步更新锚点；不能用整体框架通过或承重节点通过来代替全文逐句复审。

## 双层人话开发闭环（2026-07-20 新增）

逐句修改必须先过“删总结”，再过“口语复述”。前者移除人物不可能当场说出的作者结论、题眼、镜头句和心理归纳；后者把保留下来的事实恢复成人类讲往事时会有的时间、顺序、主语和物件承接。删掉总结不代表已经口语化，补几个语气词也不代表已经去掉总结。

典型回退是把一段过去发生的对话压成案情摘要：`问过一次。他愣了一下……我再问，他就……`。当前写法应为：`问过一次。他当时愣了一下……然后我再问，他就……`。`当时` 用来区分过去现场和现在复述，`然后` 说明第二次追问接在第一次反应之后；它们承担时序功能，不作为口语装饰到处添加。

一般开发闭环固定为：

```text
定位原句及所有副本
-> 判断是作者总结、压缩复述，还是两者同时存在
-> 先保留具体动作/原话/物件并删除总结
-> 再补必要的时间、顺序、主语或物件承接
-> 串读前两轮和后两轮
-> 同步 normal/guarded answer、lines、opener/closer、邻接锚点和原始台本
-> 重建阅读版与内容索引
-> 全仓搜索旧句
-> 运行 npm run check
-> 若改变流程、分页或运行时显示，再运行 build 与 browser smoke
```

人工检查不得只看关键词。`现在回头看`、`我才反应过来` 可以是人物真实的事后感受，只要它紧跟具体事件、没有替玩家推断他人动机；反过来，没有禁词的漂亮短句也可能仍是作者总结。机械门禁只拦截高置信回退，最终判定仍靠角色声纹和五轮串读。

人物已经做出明确动作时，不要在句尾另补一句自我责难，只为了让下一句获得安慰机会。例如已经说“我没转”，就直接交代对方仍在催，不再追加“是不是我太防着他”；主播也不必用“先别怪自己多想”把这层虚构情绪接圆。短暂确认事实即可，下一轮自然进入具体问题。

对话允许默认的信息跳跃。上一句已经说清的词，不必由另一人先复述一遍，证明自己“听见了”，再开始提问。`“先垫着”我听见了。他有没有说最晚哪天还你？` 应直接写成 `他有没有说哪天还你？`；来电人回答没有具体日期以后，也不必再归纳 `“钱下来”是哪笔钱、哪天下来，他都没说`，直接问 `那你后来怎么没转？`。只有纠正原词、确认歧义、当面对质或呈现真实情绪反应时，复述才承担新的戏剧功能；不能把关键词回声当作每轮对话的接缝。

物件已经由本人承认送达地点和实际使用者以后，不得再让人物把物件拖到麦克风旁、制造音效或补演开箱过程来重复证明归属。下一轮应追问还没回答的责任问题：这笔钱是买给谁的、它在总额里占多少、来电人为什么先前避开，以及直接受益是否伴随共同签字。感知证据只用于人物尚未承认、且声音本身能够新增事实的场合，不能为了用上一条音效而改写对话焦点。

人物质感门禁每案只要求至少一段确有口述需要的长回答。长段必须承担回忆顺序、情绪失控或复杂事实中的一种，不能为了凑“长絮叨段”数量，把一问一答扩写成重复说明。

### 禁止把争执写成口头审查表（2026-07-26 新增）

真人争执不会自动整理成左右对称的证据表。人物若连续说「给女方家三句、给男方家三句」「说高说低两边都有」「你要骂就按句骂」，随后主播再把两组话完整复述一次，场景就从争吵变成了作者复盘。

固定修法：

```text
先让人物拿出一条具体聊天
-> 主播只问这句话凭什么
-> 人物承认、辩解或闪躲
-> 再由下一问带出另一边聊天
-> 玩家选择保留材料时，只写保存动作，不再口头重念分类
```

- NPC 不能一进场就完美承认自己“说高了什么、压低了什么”。先问依据，再让其承认一句具体的没核实话。
- 主播不能镜像复述刚听完的三项或两组清单。只抓当前仍没回答的一个词，例如「收入稳凭什么」。
- 「保留完整聊天」应写成 `前后文一起截下`；「标记没核实的话」应写成 `这两句你都没问过本人`。不要让人物说「两套报价并排」「不替任何一边省半句」。
- 对称信息可以存在于材料板，不能靠两个人轮流念成口头结论。材料负责并排，人物负责怕什么、护什么、承认哪一句。

职业场景同样适用。财务、助理、供应商可以使用岗位词，但岗位词不是让人物口头生成审计报告的许可证：

- 财务窗口一次回答一件事，例如只问“回单号在哪儿”，不替来访者把审批、付款、到账念成三栏。
- 部门助理只确认自己发过的模板和当前纸面，不把私聊、批注、审批页完整归纳成责任矩阵。
- 来电人读表时可以念三行原文，却不能紧接着替玩家总结“这三行分别是什么”；主播只追她自己那一行或当前最急的缺口。
- 检查方法：删去材料名后，若这段对白仍像咨询报告摘要，而不像一个正在排队、怕越权、护饭碗或急着自证的人在回答，就退回重写。

## 微因果闭环门禁（2026-07-20 新增）

逐话轮审查之外，再给四案所有承重追问增加机器可核对的“小逻辑合同”。这层不判断一句话是否悦耳，而是阻止作者凭后台答案提问、回答越权证明、删掉画外音后上下句断裂：

- 每个正确追问必须登记 `logicContract`：当前问句依据哪句已出现的话、依据来自证言还是材料、它能证明什么、明确不能证明什么、回答新增什么，以及下一问最多能走到哪里。
- `premiseAnchor` 必须出现在当前场景无论玩家怎样选择都已经听过的文本里，不能偷用同组另一个选项的回答。
- `sourceProves` 与 `sourceDoesNotProve` 必须同时填写。看到消费行不等于知道谁付款，听到对方说“加班”不等于知道他仍在职。
- 相邻流水行不得被压成一条未经证明的钱路。日期接近、金额相似，只能先逐行说清日期、方向、金额和对方；除非材料能够追踪同一笔资金，否则必须把“七月五日信贷放款五万”和“七月十九日向 3301 转出 49,800”分开陈述，不能写成“五万进来，又去了 3301”。
- 账单总额不得被压成一个道德主语。先按可见用途与实际受益人分桶：共同消费、一方个人消费、仍未说明金额；每桶都必须有具体账单行支撑。金额本身还要过生活常识校验：一笔普通衣物、通勤或吃饭消费不能因为发生在失业后就自动升级成“挥霍”，必须比较金额、频率和同账单其他项目。若来电人只抓住较小的对方个人消费，却省略更大的共同消费，先让来电人把不满说出口，再由主播用具体金额反问，避重就轻要发生在对话里，不能只写进结案总结。订座、发朋友圈和探店号若属于同一场社交展示，只算一个行为链，不能拆成三项重复指责。关键性质问要让当事人有机会逐项承认或反驳，再进入结论。
- 第三方拒答必须保持原说话人和原证据强度。服务员说“不能替客人确认”只能带回“餐厅拒绝核对”，主播不能改写成「店里不肯说」后替店方下结论，更不能提前把带回物命名成“她的会员号”。会员号归属要等咨询者本人、订座短信或其他合法材料确认。
- 承担转场、归纳或把证据送入下一幕的 `sceneCloser` 必须登记 `closureContract`：从什么已知事实进入、场尾哪句话落住、本段只新增什么、还故意留下什么没说，以及不同选择路线下是否都成立。
- 对所有玩家可见口语做叙述视角扫描。镜头语言、身体特写、作者总结句不能借角色之口出现；能改成第一人称动作就改，必须依赖材料的就改成引用或读表，既非本人可感知又不推动证据的就删掉或放入舞台说明。
- 删除第三方描述后必须重读“上句事实 → 主播为什么此刻能问 → 当事人如何回答 → 回答新增什么 → 下一句为何成立”五轮，不能只删掉漂亮句而留下逻辑缺口。

## 跨案公共事件闭环（2026-07-21 新增）

公共风险可以让多案共享同一座城市，但不能成为作者随手解释矛盾的万能原因。每条跨案线固定登记：`个案材料种子 → 专业角色的有限见闻 → 后案公开事件 → 重估了什么 → 仍不能证明什么`。

- 个案种子先落在可操作材料和人物原话里；相邻流水只能证明先后与金额，不能自动证明是同一笔资金。
- 专业角色只能说自己知道的案件或纠纷，不得提前宣告机构结局。
- 公开新闻放在后案案尾的独立“世界回声”，由玩家主动听完；新闻不能倒推旧案具体损失、产品、账户归属或可追回金额。
- 个人选择与机构责任分开。角色对翻倍收益的期待通过借款、报价和原话呈现，不由主播贴道德标签；机构若误导或违约，也不因当事人贪心而免责。
- 房屋停工、保健品卷款等候选共同矛盾只先进入规则库。没有本案自己的合同、付款、承诺、家庭决定和未知边界，不得直接写入正文。

当前第一条登记为：案一流水 `r13/r14/r15` 种下澄川金融借款与宸直信托认购，案一小尾声由赵律师说明已有兑付纠纷，案二之后由午间新闻公开暂停兑付；边界明确不倒推案一已经损失二十万。

这条线同时执行相邻话轮门禁：`r13/r14/r15` 各自拥有来源合同，跨行问题先明说流水不能确认资金同一性；“流水圈注”回拨不再一口气念三月至七月，而是拆成三轮短问答，依次确认借款隐瞒、两笔认购和“能翻倍”的原话。后续月份及 3301 留在原有行级追问，不借跨案伏笔重复播报。

## 审查结果

### 8 万信用卡周转

## 2026-07-01 故事集标题页准则

标题页不是收麦总结，也不是目录。不能先说“这几个词不坏，坏的是……”这类主题论点，也不能把总案数、四个案名、章节功能和后续物件一次列出来。玩家还没听电话时，只需要知道热线接进来了。

标题页应该写：

```text
热线已接入。
资料在后台，她已经开口了。
```

标题页不应该写：

```text
四案放在一起说明什么。
一共有几案，每案叫什么。
第一案是什么、第二案是什么、后面会出现哪些物件。
哪些词不坏，谁拿它们省掉责任。
这一集真正要讨论的是……
```

主题论点只能放到故事集收麦、评论墙、复盘页等玩家已经听完之后的页面，而且语气要像回看后浮出来的味道，不要像作者替玩家上课。

制作规模也属于对白连续性。当前节目是林旭阳独立运营的个人直播：男，三十三岁，前互联网大厂法务，失业后做主播两年半。该履历只在整部故事第一次开篇时作为第一人称背景旁白出现一次；固定观众已经认识他，开播后不重复栏目名、年龄、前职业或电视栏目式自我介绍，直接说“开播了哈，今天继续连麦”即可。开播由本人点击，平台倒计时只作为界面或舞台动作，不得出现导播喊倒数、耳返指令、切机位口令或导播替主播收线。运营老方只能通过工作消息介入；主播停顿、喝水、静音和收播都由本人完成。每次增补暖场或功能台词时，先问这个岗位和说话方式在既有制作规模里是否真实存在。

职业身份进入亲密关系场景时要退一层。赵律师在案内可以说“落纸”“前提是”，给男友留言时应说“汤在冰箱”“我往你包里塞了个东西”“忙完再看”，不能像同事交接一样说“案卷也在包里，收播后再看”。需要埋专业物件时，先用生活动作建立关系，到收束再揭示文件袋与便签。

进入第一通以后也不能马上把目录补回来。通话眉题和 HUD 只写“热线连线 / 匿名来电 / 今晚收麦”这类直播间话术，不写“故事集 1/4”“第一案：体面”“接入下一案”。案间按钮用“接下一路麦”这类直播间口吻；案间卡片标题要用物件钩子，例如“表格 / 资料图 / 审批截图”，不要退回“下一通来电”。

## 2026-06-30 好玩度试玩补充

第一案“体面”实测路线：每段先点普通询问，再点关键追问。

评价：

- 剧情合理性：链条成立。从“奖金晚发”到社保断缴、8 万账单、催今晚转、最低还款、结婚压力，事实能一层层往下走。
- 反转性：中后段有反转，从“男方隐瞒失业借钱”转到“来电人自己也吃体面、怕承认看走眼”，灰区比单方受害更好看。
- 探索性：仍偏弱。关键追问区只有一个核心按钮，普通询问后还出现“硬点没落地/最要紧的点还没问到”这类系统提示，等于帮玩家找答案。

已处理：

- 增加“听众忍耐度”血量条，额外绕问、重复问和误指材料会消耗直播间耐心；关键追问命中和材料命中不扣，避免压力条变成倒计时。
