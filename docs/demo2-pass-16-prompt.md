## 任务 1:文档呈堂引擎(16-engine)

内容契约:

```json
"documents": [ {
  "id": "", "title": "", "intro": "",
  "rows": [ { "rowId": "", "date": "", "kind": "入账|支出|提醒|空行", "amount": "", "party": "", "memo": "" } ],
  "rowQuestions": { "<rowId>": [ { "question": "", "answer": "", "contradiction": "", "routeAxis": "" } ] },
  "crossQuestions": [ { "rows": ["<a>","<b>"], "question": "", "answer": "", "contradiction": "" } ],
  "markLimit": 3
} ]
```

- 文档查看器:整屏滚动流水单版式(复用 bill 版式基因),行可圈,圈满 `markLimit` 为止;已圈行并选两行时若命中 `crossQuestions` 配对,交叉问题点亮。
- 圈行产出 earnedQuestion(单行/交叉),写入存档与路线轴。
- **夜 2 新增「对账节拍」**:回拨开场变体之后、原有场景之前,earnedQuestions 逐条可发问(顺序玩家定),答完进入原流程。零圈行则跳过该节拍。
- 白天新增场景 kind `document`(「回后台审流水」),计入 dayBudget——案 1 白天从三地点变四地点,预算仍为 2(取舍更狠,是设计)。
- 校验:`verify:pack` 校验 rowId 唯一、rowQuestions/crossQuestions 引用存在、行日期升序、金额与 `truthBoundary` 数字互不矛盾;`smoke:browser` 补文档路线(圈两行+一组交叉→夜 2 对账→收麦)。
- 无 `documents` 字段的案件零回归。
