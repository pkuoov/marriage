# 直播间大侦探案型来源说明

本案库不是照搬真实个案，也不对应任何单一真实人物。所有案型都从公开可见的律师普法、社会事件、职场/消费/租房/平台交易讨论、情感咨询叙事和反诈研究中抽象而来，再改写成可复用的游戏结构。

## 当前已接入模板

当前 `src/caseEngine.js` 已接入 5 个可玩模板。试玩版固定使用其中 4 个，组成一个有机四案包：

```text
1. 8 万信用卡周转
2. 婚前房与共同还贷
3. 理发店排班表
4. 存款证明
5. 职场报销截图
```

当前目标不是把案型数量吹大，而是先保证每个模板都满足：

- 单人匿名连线。
- 5-6 个关键来电段，至少能支撑 20 分钟玩法。
- 一个具体戏剧物件或原话。
- 每个追问选项都有路线轴。
- 材料出现、利益转向、来电人自我修剪、第三方压力和责任落点都要有可问节点。
- 结论能处理双方互害、成本转嫁和具体边界。
- 不使用性别对立或群体攻击。

## 来源类型

- 法院与法律规则：彩礼返还、恋爱转账借赠争议、夫妻债务、婚前房产、共同还贷。
- 网络律师普法常见题：房产加名、共同账户、婚前协议、资料包装、报销和合同边界。
- 职场/消费/租房讨论：审批截图、垫款、署名、供应商返款、退款截图、押金维修。
- 情感咨询/情感博主常见叙事：前任借钱复联、同事情绪外包、控制报备、暧昧边界、资料包装。
- 平台交易和反诈：平台规则截图、代运营、虚假身份、杀猪盘、假账号会员诱导。
- 公开社会事件抽象：只抽结构，不复刻真实人物、金额、地点、原话或完整案情。

```text

4. 消费退款承诺截图
5. 合租账单和公共责任
6. 代运营合同和收益截图
7. 婚礼沉没成本加码
```

每个新增案型都要先写进 `docs/weekly-livestream-design-bible.md` 的压力系统格式，再进入代码或未来内容包。

## 抽象原则

- 不使用真实姓名、具体金额、可识别地点和原始细节。
- 不把具体责任偷换成性别、职业、地域或阶层标签。
- 双方互害可以写，但必须拆清行为链条、严重程度、实际成本和后续边界。
- 每个案型必须能生成一通单人匿名连线；另一方信息只能通过咨询者转述、截图、录音或后续补充进入。
- 每个案型必须包含可追问的迷惑点：假话、含糊话、不愿意说、小承认掩护大隐瞒、真话但留白。
- 四案故事集固定四案顺序；剧情必须先有完整动机链，再拆成你一句我一句的对话分支。
