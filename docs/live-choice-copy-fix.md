# 提问面板文案修订单（live choice copy fix）

日期：2026-07-04
问题：双层提问面板的组标题「往哪头追」与说明「这段只能定一次。问偏了，弹幕会散。」不像人话——"哪头"是实物两端的用法，"定"无宾语，"弹幕会散"不是真实弹幕语感。本质是把规则解释套了层黑话马甲，仍过不了"主播会不会在麦上嘟囔这句"的读稿测试。后续版本的「先问两句 / 接着追」不够清楚，「随口问问 / 选一句往下追」又没有把关键选择和非关键选择说透。
修法原则：规则清楚优先。标题直接区分两种经济：「普通提问」不推进剧情，「关键选择」会推进剧情；按钮本身也显示「普通 / 关键」，不能只靠颜色或位置让玩家猜。

## 修改 1：`src/ui/sceneQuestions.js` 两处 choiceGroup 调用

自由层，标题与说明都替换：

- 标题，旧：`随口问问` → 新：`普通提问`
- 说明，旧：`问几句都行。` → 新：`不推进剧情，可以多问。`
- 按钮标签：新增 `普通`

承诺层，标题与说明都替换：

- 标题，旧：`选一句往下追` → 新：`关键选择`
- 说明，旧：`这句问出去，就收不回来了。` → 新：`会推进剧情，只选一句。`
- 按钮标签：新增 `关键`

## 修改 2：`scripts/verify-logic.js` 同步断言（UI-001 内）

- 新断言：`assertIncludes(questionHtml, "普通提问", "随意提问区标题必须明确这是非关键选择");`
- 新断言：`assertIncludes(questionHtml, "关键选择", "正式追问区标题必须明确这是关键选择");`
- 新断言：`assertIncludes(questionHtml, "不推进剧情，可以多问。", ...)` 与 `assertIncludes(questionHtml, "会推进剧情，只选一句。", ...)`。
- 新断言：普通按钮不得同时拥有 `data-scene-question`，关键按钮不得同时拥有 `data-scene-dialogue`。

## 验收

2. `npm run smoke:browser`（回放脚本未钉这两句，预计无需改）。
3. 可读性测试：玩家扫一眼应能知道「普通」不会推进，「关键」会推进，且每个按钮只能属于一种类型。
4. 提交信息建议：`fix: humanize choice panel copy`。
