# 第二批次要 NPC 台词声纹审计

日期：2026-07-17
范围：四案白天场景与后台回流里真正出声的次要、麦外 NPC。

## 处理结果

本批审了 16 位逐案麦外角色。案一前同事、两案常客、案二店长当面句、案三介绍人与表姐原本已有明确防御动作，保留不动。必要修改集中在容易写成“证据说明员”的人物：案一服务员、案二开店朋友、案四财务经办、供应商项目员、仓库管理员和部门助理。

另外给 8 条由 NPC 提供的后台材料补了 `speakerProfileId`。这些材料以前只有 `source: dm` 或文字标题，机器能读出内容，却不能确认是谁的固定声纹。`PACK-010` 现在会检查该 ID 必须存在，并且必须列入本案 `castProfileIds`。

## 典型碰撞与修法

案四原稿里，财务经办、供应商项目员和部门助理都频繁使用“不能替你说”“不在这一页”“只能带回缺口”。三个人虽然事实边界正确，听起来却像同一位冷静证据员。

- 财务经办现在说：“没回单号，先别报付款。下一位。”她关心输入字段和窗口队列。
- 供应商项目员说：“账户我没经手，这句你别让我接。”他关心客户关系与自己的经手范围。
- 仓库管理员说：“我这儿只认出货单。”他把话压回手边纸单。
- 部门助理说：“我只替你核字……再多一句不说。”她留下自己执行模板的痕迹。

四种表达仍指向同一事实边界，没有新增付款、账户或返点结论。

## 连续性护栏

- 案一会员号仍未核验；服务员拒答不等于确认身份。
- 案二店内标准表仍不能替 Tony 的私人推进表作证；另一位女客只证明另一张同款表存在。
- 案三持续收入与 MBA 学费来源仍未知。
- 案四审批、付款、到账仍是不同凭据；对接人已知，最终收款账户仍未知。

## 后续维护

第三批生成的角色台词报告必须同时收集显式 `speaker` 和后台 `speakerProfileId`。新增 NPC 材料若没有人物卡，不得只用模糊 `source: dm` 假装完成声纹归属。
