# 人工记录触发试玩回标题页：修复记录

用户报告两次突然回标题页，第一次在提到转八万附近，第二次继续点击后再现。2026-09-09 用户确认是回到游戏标题页，并非窗口关闭或白屏。

## 复现与根因

在 `http://127.0.0.1:5175/` 继续存档进入咖啡厅，当前为旁白第一句。仅执行 `touch docs/unfinished-backlog.md`，页面立即回到标题页；浏览器没有捕获到脚本错误。此前两次“仅记录”的反馈都会写入这份待办，因此触发相同过程。

开发服务原先递归监听整个工程，仅排除 `.git / dist / node_modules / .DS_Store`。Markdown、skill 和审稿报告的写入也会发出 SSE `reload`，页面收到后执行 `location.reload()`，重新显示标题入口。该复现无需点击转账或推进到某句台词。

## 修复

- 新增 `scripts/lib/dev-reload.js`，仅放行 `index.html`、`src` 下的运行代码／样式／JSON、`content` JSON 与 `assets` 媒体资源。
- 文档、skill、人物与章节笔记、测试脚本、构建输出、媒体审阅 HTML、临时文件不触发刷新。
- 增加三项资源分类回归测试并接入 `npm run check`。实际代码和媒体更新仍保留自动刷新。
- 只重启本次启动的 5175 服务，继续使用原地址，未使用 `fresh=1`，未清除用户存档。

## 验证

- 新增三项过滤回归测试通过，覆盖文档记录、真实运行资源、临时文件及路径格式。
- `npm run check` 与 `npm run build:h5` 均通过，完整检查包含 122 项逻辑测试、8 份叙事样本及 13 项编辑器测试。
- 修复后在同一 5175 页面继续进入咖啡厅并推进至第二条旁白，同时更新待办、skill 和生成报告的时间戳。页面保留该条旁白及继续控件，没有返回标题页，浏览器未捕获脚本错误。
