## A 部分：机制接线

### A1（P0）弹幕选择 ↔ 防备系统

- **设计**：每案 2–3 个关键节点，玩家从 2–3 条弹幕中选择念哪条（或不念）。
  - 念尖锐弹幕：触发「施压」——逼出坦白/材料，防备 +1；
  - 念共情弹幕：不推进当前谎点，防备 −1，解锁羞耻点完整版坦白；
  - 不念：中性，走现有默认线。
- **状态**：新增 per-case `guardLevel`（0–2 足够）。防备 ≥1 时，后续带「防备变体」的节点切到防备版台词（**变体已写好，只需接线**）。
- **落点建议**：优先接在已有弹幕打断处（案 2「收了好处装什么受害者」、案 4「弹幕说我蠢」），再为案 1/案 3 各补 1–2 组弹幕文案。
- **实现**：状态字段进 `state.js`（记得补 migrate 与 baseState）；判定逻辑放 `src/runtime/`（建议新文件 `guardModel.js`，不要塞进 sceneAdvance）；选择 UI 复用 liveCounter beat 的交互样式。

### A2（P0）耐心明账 + 人设参数化

- **设计**：耐心以**台词和主播观察**呈现（如主播内心旁白「她的声音开始发紧」），底层数值可见于 debug；每案配置耐心参数：
  - 案 1 沈：中等，戳「共同消费」加速消耗
  - 案 2 何：短、恢复快（爆发后自己缓）
  - 案 3 林：长，但「彩礼卡/她妈」话题骤降
  - 案 4 陈：长（职场新人不敢挂电话），但消耗后防备升得快（与 A1 联动）
- **代价真实化**：耐心崩 → 当夜提前收麦，本夜未拿到的材料不补，第二夜走「若没有带回关键物件」弱开场（**变体已存在**）。
- **实现**：参数进 case JSON（新增 `patienceProfile` 字段，记得同步 `contentCase.js` 字段白名单与 verify）；崩溃流程复用 `casePatienceLost` / `recordPatienceLostState`。

### A3（P1）假说下注

- **设计**：每案第一夜收麦后插入一屏：「今晚你怎么看？」2–4 个假说选项（如案 1：他蓄意布局 / 他失控了 / 她也有份）。
  - 不影响流程可达性；影响主播第二夜追问的措辞前缀（每假说 1–2 句变体，内容增量小）；
  - 结案卡新增一行对照：「你昨晚押的是 X，材料最后指向 Y／仍未可知」。
- **实现**：`hypothesisPicks` 进 state；结案卡模板在 recapModel / 对应 JSON 收尾字段扩展。

### A4（P2，可后置）KPI 经营循环

- 每晚收麦结算屏：在线曲线、打赏、投诉风险三行字（不做图表化数值堆砌）。
- 施压路线数据涨 + 投诉风险积累；克制路线数据平 + 老方措辞升级。
- 四案累计 → 尾声在现有「数据好/坏」两变体基础上扩展为「深夜档保住 / 并入娱乐区」两个 demo 结局段落（各一屏文案）。

### A5（P2，可后置）跨案线索板

- 基于 courtRecordView 扩展跨案材料墙：玩家可把各案材料钉墙、连线。
- 连出宸直链（澄川借款→宸直认购→三十万到期→十万投店）→ 案 4 后解锁隐藏短戏：主播提前向赵律师预警；爆雷新闻推送增加「你早看见了」变体一屏。

## B 部分：戏剧时刻

### B1（P0）闯入时刻分叉化

四案已有的闯入事件 +「主播可以」三选，现状殊途同归。改造为**真实分叉三个状态**（不分叉剧情线）：

| 案 | 闯入事件 | 三选分叉的状态 |
|---|---|---|
| 1 | 对方消息轰炸 | 来电人防备 / 她是否继续念后续消息（材料范围） |
| 2 | 警察敲门后回拨 | 防备 / 她何时坦白民警细节（本夜 vs 逼问后） |
| 3 | 男方刷礼物申请连麦 | **他同意公开的材料范围**（三选已是谈判，让结果真的不同）/ 数据 |
| 4 | 同事大群发声明 | 她回群的措辞强度 / 同事后台留言的态度变体 |

- **规则**：闯入三选限选一次、不可回溯、选项无安全项标注。
- **实现**：每案为三选各写 1 段短后续变体（2–4 行台词/一条材料可见性开关）；防备走 A1 的 `guardLevel`；材料范围用现有材料可见性机制（materialVisibility）。

### B2（P1）跨案知情负担（宸直 dramatic irony）

- **案 3 核心场**：来电人说出「三十万在宸直、九月底到期」时，给主播三选：
  1. **说破**（越界警告：宸直有兑付纠纷）→ 防备 +1、数据 +、家里群反应变体；
  2. **暗示**（现行台本的克制版，设为其中一个选项）；
  3. **沉默** → 无即时反馈；尾声爆雷新闻处，为「曾沉默」的玩家增加一行主播独白变体。
- **案 4 次级场**：供应商/理财相关话题出现时给一次轻量版（暗示/不提）。
- **约束**：三个选项都不判分；说破不是「正确答案」——赵律师广告间隙可补一句「没到期就下结论，你也在赌」让说破有伦理毛边。

### B3（P1）每案一个「无安全选项」时刻

- 案 2：老方商务函同步处，「继续问」→ 数据涨 + 投诉风险 +1（进 A4 累计）；「不提店名只问人」→ 材料范围收窄（某条店侧材料本案不可得）。两边都有真损失。
- 案 4：领导批注到达处，新增选择：「提醒她确认表的责任栏」→ 她感激但犹豫加深（结尾群消息措辞变弱）；「只对账不提醒」→ 边界守住，尾声短信多一句「那行字我后来才看见」。
- 案 1 / 案 3 各设一处（建议：案 1 = 是否替她把「别转」说死；案 3 = 是否让男方连麦继续）。
- **规则**：结案卡「你今晚的选择」一栏诚实记录，不评价。

### B4（P0）双层裁决：账 / 人分开收尾

- 结案时把现在的一段式收尾拆成两次表态：
  1. **账怎么算**（沿用现有 accusationChoices / 收尾判断）；
  2. **人怎么办**（新增 2–3 选：这段关系的去留 / 她该怎么对自己）。
- 两层允许矛盾；尾声回声在现有 pragmatic/affirm/accompany 基础上按「账×人」组合挑选（不必做满矩阵，每案挑 3–4 个有戏的组合写变体，其余落默认）。
- **实现**：case JSON 收尾结构扩展一组 `relationJudgement` 选项；`contentCase.js` 白名单与 verify 同步。

### B5（P1）主播伤口线（纵向弧光，案 4 汇合）

- **泄露机制**：全 demo 累计施压选择数 ≥ 阈值时，案 2/案 3 各解锁一句主播泄露往事的短台词（各 1–2 句，写进对应 JSON 的追问变体）。
- **汇合场（案 4 结案前）**：老方最后通牒 + 来电人最后的犹豫，给终极三选：
  1. **播出自己的往事**（「我也被人这么借过钱，那笔没回来」的完整版 3–5 句）→ 来电人彻底交底（解锁一段补充坦白）、数据爆、收播后赵律师场景变体（她听到了）；
  2. **只给方法不给自己**（现行线）；
  3. **沉默让她自己决定** → 尾声陈的短信变体（更独立的版本）。
- **主题闭环**：主播整个 demo 都在要求来电人坦白余额，最后一案轮到他自己。收播后妻子场景按选择给 2–3 行变体，不说教。

### B6（P2）沉默机制化

- 防备 ≥1 的指定节点，「(不接话)」成为唯一降防备的选项；她的【停顿】自续台词（已有内容）作为奖励呈现；代价：本轮追问机会消失（耐心不退还）。
- 每案 1–2 处即可，优先案 2、案 4。
