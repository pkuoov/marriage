# 四个主案、两个快案：剧情与对白复审

日期：2026-09-07。状态：**仅审查；六个案件 JSON 未修改。** 本文的修改方向都不是已接入台词。

采用 [剧情与对白复审流程](../../project-skills/case-scriptwriting/references/story-review-workflow.md)。依据快案《什么都不图》的人工批注，结合既有四份主线审计和另外两个快案的接话复审，重新核对当前真源、实际场景配置与关键渲染逻辑。

## 总体判断

六案都有可以保留的冲突，不需要统一推倒重写。当前最影响体验的，是**作者知道的完整剧情、玩家已听到的内容、人物此刻正在做的事没有始终对齐**。换几句口语词不能解决这些问题。

这轮发现的重点：

1. **全局时间与案内材料仍会打架。** 案一在 7 月 15–16 日播放，却拿到 7 月 19 日已经转出的流水；彩礼案也有六月材料与“上周／前几天”的连接问题。
2. **主播偶尔替人物增加原话，再去反驳。** “本月第一次没转”被回拨改成“昨晚只说奖金晚发”；“跟妹妹出去”被改成“姐妹俩”；职场案的九天时间差反驳了尚未完整说出的理由。
3. **解释已经完成，后面的玩法仍要求重新问。** 部分是可选路线与固定续接不一致，部分是证词墙重新设置了一个人物已经放弃的立场。
4. **人物确实有好看的歪理，但经常被要求自己总结或接受教育。** “照片修好了不发浪费”“我家就差两千要看态度”值得留；“两边安排不对等，我认”这类作者分析应优先退出人物嘴里。
5. **旧合同会把已修过的问题带回来。** “同意代投”不等于“绝无恋爱误导”；“用她的会员号”不等于“她操作订座”；快案三既然是读文，意图合同就不能继续要求缺席作者被主播问到后承认。

优先级：P1＝影响事实、发现公平或核心推断；P2＝影响接话、人物、节奏及行动；P3＝维护与表述。这里只评内容和接线，不声称完成了全工程代码、UI 或音频回归。

## 第一通：《账单里的八万》

真源：[01-credit.json](../../content/packs/steam-demo-01/cases/01-credit.json)。旧账本：[案一主线审计](../case1-spine-audit.md)。旧账本的债务／受益区分继续使用，订座人及日期判断以本轮问题为待修事项，不能称为全部锁定。

### 事实、利益和发现顺序

沈已收十四个月固定半薪，累计 24.5 万，房租另付，实际自报余额约 1.16 万。她想保住余额与“不欠情分”的说法，拿回放去回绝男友；男友给过钱、维持过排场，想让她拿八万救卡，又不愿交代未知消费与部分资金来源。双方共同消费约四万，明确男装约五千，至少三万五待解释。

| 版本／材料 | 为什么这样讲 | 玩家应取得什么 | 能改变什么／不能证明什么 |
| --- | --- | --- | --- |
| 奖金晚发，临时垫八万 | 男友让当晚转钱显得可行 | 社保中断、之后的离职结算通知、男方承认改名 | 待发补偿不是已到账奖金；不能确定完整还款能力 |
| 分住、工资卡没交她 | 沈先缩小经济联系 | 固定半薪；白天房租行与受益人回答 | 她长期受益；不自动承担男方名下债 |
| 男装花五千 | 让八万听起来主要是他乱花 | 共同消费与一万二设备；逐项分清 | 叙述有选择；未知三万五仍未知 |
| 至少还剩十五万 | 男友把累计转账当作她现有储蓄 | 他的估算与她实际余额 | 解释他为何找她要钱；不能把估算变成事实 |
| 只要主播说别转 | 沈回避自己说明花销 | 她准备如何用回放 | “今晚不转”与“以前不用交代”分开 |

主线可继续沿用：停转引发追问 → 男友催八万 → 查消费和旧给付 → 取得有限流水 → 查到房租／借款 → 新消息交代补偿和十五万估算 → 沈报余额与回放用途 → 双方各自谈账。日期先修清，才能把这条线当作闭合事实。

## 第二通：《职场报销截图》

真源：[04-workplace.json](../../content/packs/steam-demo-01/cases/04-workplace.json)。旧账本：[案四主线审计](../case4-spine-audit.md)。文件编号04是稳定 ID，玩家第二通。

### 事实、利益和发现顺序

陈要追回 6.8 万，又想保住以后接活动的机会。她已争到负责人署名，为刷卡自己申请提额；不愿暴露看过报备却没做、发票一直压在手里的事实。同事保住经办与供应商联络位置，用“会补流程”维持等待；供应商返费是否到他账户仍未知。领导夸过活动，不等于知道个人垫款。

| 版本／材料 | 保护的东西 | 应当问出的变化 | 边界 |
| --- | --- | --- | --- |
| 同事让我垫，公司没报下来 | 她不想失去机会 | 她主动争活、提额；群流程与相反私聊 | 主动接活不能把公司成本销成她个人消费 |
| 审批通过，再等几天 | 同事维持控制，她避免公开追问 | 三次旧立项；报销编号未见；发票未提交 | 没见申请不等于公司任何地方都没申请 |
| 他是经办，他会补 | 她不想被问为什么没报备 | 发票为什么压在抽屉三周 | 不能用通用窗口代替公司内网查询 |
| 群里终于认了，是否不用再发 | 想用一句承认结束自己的风险 | 认垫款与月底提交／打款仍是两回事 | 这是有新消息触发的合理反复，应保留 |
| 准备发群消息 | 从等同事变成自己行动 | 发票、申请入口、编号、日期按先后确认 | 不用她公开认完一套人生道理才允许追款 |

建议主线：想要活动 → 看过规则仍先刷 → 旧图挡住催问 → 识别立项不是报销 → 发票为何未交 → 群里承认又撤回／私聊施压 → 她决定自己留下追问并提交。供应商路线另走，不抢“我终于发出去了”的结尾。

## 跨案一起处理的事项

### 陈述块重排后，技能的“先说后问”必须按运行时解释

`statementStagePromptExchangeHtml` 先渲染该块所有场景的前置话、版本和后置话，之后才让玩家追问。因此案一[0,1]里，场景1问“这个月的钱没来”，不能仅靠场景0的问答收段提供前提；Tony[4,5]也不会天然实现旧审计要求的“先问完警察、再讲十二万”。这些不是单句病句，需一起审陈述块边界。

### 同一句笑话，写在 JSON 不等于玩家看见了铺垫

证词墙界面主要呈现 `acts` 的 opener、statements 与 reliefBeat，前置对话另走 prelude；不会顺手把普通场景的全部 `version` 播一遍。职场“大拇指先到账”要保留，先确认母亲点赞的那一段真正接入，而不是把笑话删掉认定“不自然”。
