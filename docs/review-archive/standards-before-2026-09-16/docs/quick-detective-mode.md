# 直播快案：来电对质与单人口播

## 目标

快案有两种入口。来电对质把一通有所隐瞒的咨询压缩成十几分钟：玩家先整段听完，再把原话逐句拉回，按住可疑句以后由林旭阳当面追问。单人口播则把一篇公开长文、回应和必要背景压成若干段：每段材料上屏以后暂停，玩家选择主播先从哪个成立角度评价。快案不设置分数、弹幕补线或评论区裁判；玩家参与的是主播怎样切入，而不是替法院判事实。

快案的耐心按陈述段计算。左右浏览和反复听原话不扣耐心，只有确认了一句完全没有可追问线索的话才扣一格；未耗尽时只在原句下显示「耐心 −1」并缩短状态条，不追加弹幕、听众评价或答案讲解。耗尽后才出现直播间开始失去耐心的反馈，并从本段重听；进入下一段时使用新的耐心条。界面不显示数字页码或答对数量。

## 第一关：《什么都不图》

林旭阳直播之外也替登记过的单身听众做少量同城介绍。一位二十四岁的服装销售因此请他介绍对象。她先用工作、收入、名下小两居和父亲的经历证明自己能独立生活，随后把条件放到月薪四五千、没房、年龄大她五岁以内。主播给出符合条件的普通对象时，她不直接拒绝，而是用“不够了解”挡一下，再把安全标准加到主播熟悉、自己经商、家里稳定的男性。

当前按 JSON 的 `disclosureRounds` 分四轮披露：售货工作、家庭与出资、本人检查顾虑、实际择偶要求。每轮只询问当时已出现的原句；详细轮次与台词以生成阅读稿为准，不沿用旧两轮摘要。主要问点包括：

- 亲生父亲只能偶尔帮人看店，给她一百万元买房的“爸爸”究竟是不是同一个人。她先坚持“我一直叫他爸爸”，被主播逼着只回答是否亲生以后才承认不是，再用隐私和自愿赠与挡住真实关系。
- 她在讲相互扶持时偏偏拿自己不能生孩子举例；首轮主播不追。玩家选中这个疑点以后，她先反驳，主播短追一句，她才承认做过检查。
- 她口头接受月薪四五千、没有房的对象，也说不会让男方养她；实际又避开符合标准的普通上班族，指定主播熟悉的经商男性，还希望对方减轻总价两百万元房子的贷款压力。
- 她把一段关系散掉归因于不会讲好听话，求主播背书时却立刻恭维、改称呼并让他先替自己说好话；玩家追问的是这究竟是不是分手的根本原因。

每次对质只处理一处矛盾。来电人不完成自我审判：她先淡化、强调隐私，再替自己的双重标准找理由，最后因主播拒绝背书而不耐烦。反差来自她在普通问话里说得从容、被逐项问回时却不断改换理由。

林旭阳拒绝介绍并挂断以后，还要完成两段口头复盘。第一段把两个“爸爸”、口头低条件与实际筛选、不能生育例子的下意识泄露、临场软话重新放在一起。第二段只落行动判断：她没有说清一百万元是谁给的，也没有把自己真正接受的对象条件先说全，却要借主播信誉接触条件更好的对象。主播因此拒绝介绍和背书；出资人身份、双方关系、检查的医学含义和她是否另有伴侣仍然未知，不能由称呼和给款替她补一段人生故事。

## 第二关：《那晚没回消息》

2026-09-07 接入稿为十二组陈述、四轮、六段对质。当前可玩顺序：

1. 六组初述建立相处、条件、截图来源和六分钟消息差。先问包的来源、公开评论与当时身体状态；收礼和需要交流可以同时成立。
2. 两组重讲当晚，顺着“有人又点了一轮”问出妹妹的男性朋友，不再重复揭示醉酒。
3. 紧接着问她第二天怎样向男方解释。她说漏“我妹妹那个朋友”，男方才追问；声音线索不依赖他／她字幕。
4. 她自己翻出旧动态，再问连续两晚外出与十号发八号照片。她可以用生日、毕业聚会、没喝醉分类，也可以反驳主播。男方实际看过哪些动态仍未知。

最后她才问要不要联系、能否给一句照发的话。主播不能保证挽回，建议先停下追发；她说“我再想想”。收麦复盘只回顾已经取得的信息，不强迫人物接受教训，也不把异性同行或夜生活单独当作越界证据。

## 第三关：《写给女演员的长文》

单人口播当前四轮：人物与虚构标注 → 三千万及未转的五千万美元、女方回应 → 传闻与中间人转述 → 三条条件回扣认全文。每轮三个成立切口任选一项，未选项不判错。

材料先给公开行为和来源，不抢先替玩家分析动机。职业风险可能解释为什么急于平息争议，但不能确认女方授权中间人，也不能证明长文中的私密指控。作者不在现场，不安排主播逼他认错。

末段的三种点评分别看诉状外条件、未公开材料施压与虚构标注。固定结案只有一页：直接批评自己写虚构却要求对方认全文，女方未答三千万单独说；不凑双方各打一遍的判词。本轮未重新核验原有现实法规来源。

## 后续口播案件怎样起稿

后续快案四另记为许愿型来电：围绕彩礼、女性力量、付出与主播 battle，玩家选择对应话术反击。目前仅记录题材，未新增可玩案件或确定分支；见 [诉求主线与快案四记录](review-archive/caller-request-spines-2026-09-08.md)。下列现有模式说明不代表已经实现这一新玩法。

先按 [剧情与对白复审流程](../project-skills/case-scriptwriting/references/story-review-workflow.md) 找实际争议、公开动作、说辞缺口和当前疑问，再决定暂停点。当前轮数是本案的配置，不是后续案件的配额；背景先后随当前疑问安排，不必固定放在第二段。观点必须有本轮已读材料支持，各选项能独立接下一段。结案长短随实际未解决的问题决定，不强制追加高概率动机故事。

## 玩家流程

1. 从标题页进入“直播快案”，先看到案件选择页，不覆盖四幕主线进度。
2. 每宗快案只显示稳定的两位案件编号、标题与完成状态；已完成案件保留对勾，也可以重玩。预计时长不放在玩家界面。
3. 来电案按本案配置分轮，使用「来电人陈述／逐句追问」。口播案在材料后的暂停点使用「长文精华／主播先评哪一处」。阶段提示只区分节奏，不解释答案；普通播放没有实时评论。
4. 来电逐句回放每屏显示完整原句和“询问这句／不询问”，玩家选择询问后才播放具体问题。误问同样先播主播问句，再播来电人回应，回应读完扣当前陈述一格耐心；回到所选原句后显示简短状态，不替玩家排除答案。左右浏览和重听不扣耐心。直播间反应只在耐心耗尽后出现。

来电快案的错误 `issueOptions` 必须填写实际口播的 `question`，不能只写内部 `label`。多个原句共用对质时，可配置 `confrontationOpeningLines`，先承接所选原句，再播放共用 `confrontations.lines`；仍按共用对质 ID 记完成。`activeIssueId` 保存入口，`missPhase` 保存问句／回应进度，`missPenaltyPending` 保证回答读完只扣一次。旧版已扣费的反馈不补扣，旧版共用对质的行偏移不插入新开头。未完成当前轮的追问回到所选原句；换轮才重置选句。
5. 来电案每按中一处成立原句，林旭阳用完整问句当面打断；口播案每选中一个成立切口，林旭阳完成当前配置的点评，本段随即结束，不要求把另外两个角度全部点完。
6. 来电案在当前轮必要方向全部问完后推进；口播案使用 `completionMode: "any"`，任一有效点评完成就推进。最后由主播按固定结论收束，玩家的选择改变观点顺序与重音，不改变事实结局。
7. 挂断后继续留在主播视角，按当前已经问清的内容收住。可以简短复盘，不必再补一套动机解释；完整与提前收案各按所见信息判断。只有最后一页的最后一句显示后，案件选择页才打上完成对勾。

## 舞台呈现

- 整通快案固定在同一间直播间。来电案由林旭阳与当前来电人分居两侧；口播案只保留主播立绘，另一侧显示公开材料卡，不伪造当事人在线。
- 首次听麦使用宽气泡整段显示，来电人提亮、主播压暗；回放时中央改为逐句记录条，控台 `REC` 亮；打断后恢复窄气泡逐拍攻防，控台 `LINE` 亮。三种表面不依赖页眉也能分辨。
- 舞台层只显示人物或材料名称与当前状态。不得显示“第 X/Y 屏”“对质 X/Y”或答对比例。已经问清或点评的原句可做完成标记，但不能标“正确答案”。
- 案件入口遵守观众可知边界：只写“有人来电”和她表面上的求助，不用简介替玩家概括学历、职业、相识渠道、消费、失联导火索或自我归因。所有具体案情从接通后的第一句开始披露。
- 来电人立绘是玩家侧的戏剧化想象，不代表节目获得了摄像头画面；主播和证据系统不得从她的表情、衣着或背景推断事实。

## 内容与版权边界

本模式受用户提供的公开视频与公开争议启发。第一关的人物、金额、家庭经历、台词和结论均为原创虚构。第二关依据 `BV1iGKG65EJ3` 重新核对原视频的公开因果骨架；人物姓名、具体年龄、婚恋机构、聊天措辞、对质台词和舞台结论均重新创作，也不把异性在场单独写成越界证据。第三关只借用“指向真人的长文标注虚构、财产诉讼、代孕争议、公开声明与中间人自称调解同时出现”这一结构，人物、机构、标题、转账打法、三条条件和全部台词均为虚构合成。求和动机可以作为高概率推断，但调解授权仍缺女方本人材料；国内监管禁止代孕，也不被游戏写成所有参与者自动构成同一刑事罪名。

## 数据与代码

- 内容真源：`content/packs/steam-demo-01/quick-cases/*.json`
- 角色真源：`content/characters/cast.json`
- 纯状态机：`src/runtime/quickDetectiveModel.js`
- 纯界面模块：`src/ui/quickDetectiveView.js`
- 内容入口：`content/packs/steam-demo-01/manifest.json` 的 `quickCases`

案件选择顺序只读取 manifest 的 `quickCases`，不在界面里另写一份列表。每个快案必须提供唯一 `id` 和两位数字 `caseNumber`；编号属于内容身份，不随列表位置临时重排。完成记录独立保存在玩家存档中，重开主线或返回标题页都不会清除。

新增来电快案按当前材料与对质前提配置 `confrontations` 和 `disclosureRounds`，不设统一轮数。口播快案设置 `format: "solo-commentary"`；各段登记实际 `issueOptionIds` 与对应 `requiredConfrontationIds`，并设置 `completionMode: "any"`。每项 `issueOptions` 必须用 `sourceAnchor` 逐字绑定本轮已经上屏的一句材料，`label` 只概括点评切口，不得偷写整段结论。每项点评用 `basisTurnIds` 指向当前材料，台词保持主播单人。当前段完成任一有效点评后必须直接接下一段；恢复存档时若该段已有任一完成项，也要自动续播。`ending.summaryPages` 按当前需要收束，不强制分三类页面；`confirmed / unknown` 继续约束口播，但不上屏替主播说话。
