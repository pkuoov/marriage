# 编剧工作流

现行创作规则见 [项目方向](../project-skills/case-scriptwriting/references/current-project-direction.md)，字段与模式见 [内容 Schema](content-pack-schema.md)。本文件说明怎样开展工作，不另规定剧本结构。

## 按任务选择起点

- 局部修句：定位稳定 ID，读前后完整交换与真实播放字段，修相邻承接及相关副本。
- 整案改稿：连读实际路径，记录人物诉求、知情先后、线索来源、行动与回收，再决定哪些段落需要重排。
- 新案：先写能连读的场景或提纲，按材料和人物需要选择交互模式；原创性来自具体创作，不用固定数量的热点拼接证明。
- 只审查或只记录：交付定位与判断；用户要求接入时再修改。已有接入授权无需被历史“待确认”重复阻断。

编剧、角色视角和连续性检查是可按需使用的审读视角。同一人可以完成；不要求五个 agent、固定阶段文件或每次完整跑七个 skill。是否委派按当前用户授权和工具规则决定。

## 写成能接上的对话

每次转折核对“上一句提供了什么、此时为什么问、回答在承认或回避什么、下一问据何成立”。已经知道的归属可以追用途，不能重新伪装成秘密。可跳过的询问不能是固定续文唯一的信息来源。

隐瞒落在具体保护对象上：犹豫报数、偷换时间范围、把索取说成承诺、把花销说成投入。对方可以答偏、争词和反击；语塞本身不证明有罪。不要为了满足检查添加短答、长答、打断、噪声、第三方或双方过错。

段数、时长与收尾长短由当前内容决定。五段结构、结尾先行等是可选方法，不是准入条件。不要强制评论墙、责任分层口播、认错或回暖。

## 接入与验证

按 [运行时接入](../project-skills/case-scriptwriting/references/runtime-content-integration.md) 同步 `lines`、兼容 `answer`、场尾、回拨、引用和存档身份。按 [对白审读流程](../project-skills/case-scriptwriting/references/story-review-workflow.md) 记录具体问题；对照库按需取例，编辑器不是唯一修改入口。

生成命令为 `npm run content:index` 和 `npm run content:script`；生成稿不手改。连续台本用于按当前顺序串读，导演稿检查演出，完整稿查字段与未播放内容；完整稿里存在一句话不代表玩家能听到。

内容／逻辑检查运行 `npm run check`，改变交互或顺序时再构建 playable 并走受影响路径，UI 按 PC 目标尺寸查看截图。具体覆盖见 [验收指南](qa-test-guide.md)。不以定点载入、关键词命中或模型自评代替连续游玩与语义审读。
