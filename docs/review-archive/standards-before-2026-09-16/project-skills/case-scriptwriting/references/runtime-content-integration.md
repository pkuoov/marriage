# 运行时内容接入

本文件记录易失配的技术边界，不定义人物口吻。先核对当前消费者；字段名相同不保证不同交互模式采用同一顺序。

## 来源与播放

- 真源是内容包及相关人物资料。生成索引、导演台本、连续阅读稿、角色对白报告由脚本生成，不手改。
- 普通场景通常按 `beforeVersion → entryQuestion → version → afterVersion → 问答` 播放。`afterVersion` 不能依赖还没问出的答案。`sceneCloser`、`hostDisclosure afterScene` 应在整组追问完成后出现。
- 证词墙按 `interactionMode` 读取 acts、PRESS 解锁、PRESENT 和后续交换，不回落到同场旧 `questionOptions`。两幕各自完整陈述后盘问，命中对白与实际说话人顺序一致，隐藏句只在解锁后可见。
- `sourceAnchor` 对应实际已播陈述；存在 `revisedVersion` 时核对 `revisedSourceAnchor`。锚点引用不能添“只有、全部、一定”。`basisTurnIds` 只指已播话轮。
- `lines` 存在时核对真实播放路径；`answer` 保持兼容语义一致。多人对白、`reactionLine`、场尾、回拨、尾声和“上一问”共同检查，不能只改搜索首先命中的副本。
- 内部 `logicContract`、`truthBoundary`、`body.access` 描述来源与限制，不自动渲染给玩家。`body.sourceNote` 若显示，只保留材料出处所需信息。

## 顺序与存档

- `questionSequence` 使用稳定选项 ID，`completedOptionIds` 记录连续完成前缀。`choiceMode: sequence` 的现场交流使用 `completedChoiceIds`。不要靠数组位置或文字判断身份。
- 中间回答不得提前标记场景完成、显示场尾或开放退出。重载后继续下一步；旧互斥选项已选不等于新顺序全部听完。
- 后续交流不能抹掉前面已发生的推荐位损失、发送或退款。保存裁剪、迁移、当前内容刷新和历史回放都要实测，不能只调用一个迁移函数宣称读档通过。
- `careChoices` 当前顺序模式保留已有 ID 和存档类型；变更其结构前读消费者和兼容代码，不另存一套互斥剧情。
- 不改变尚未触及的材料判断模式。错误材料反馈说明操作未成立，不暴露正确组合；soft PRESENT 的状态不能因命中与否提前泄题。

## 跨夜与信息

- `overnightStructure` 存在时检查当前回拨唯一来源；`earnedItems`、行动 ID 和开场前提对应，不能保留互不相连的双套开头。
- 固定续文只依赖必经信息；可选调查独占的事实应有条件话，或另有可信的固定来源。不能假称玩家去过没去的地点。
- 被删场景的证人、材料来源和后续回声一起清理。具名跨案机构可以延续，不凭半姓、同额或日期巧合制造另一个身份结论。
- 可归因的新材料出现前不要在挂断预告、按钮或标题上披露其内容。

## UI 与验证

- 一屏按当前阅读页呈现，姓名、角色 ID、立绘与对白一致。语音连线立绘不是摄像头证据，主播和弹幕不能据此观察来电人房间。
- 材料原件必须可读，关闭后恢复位置与焦点；标注和已完成状态持久化。弹层内 Enter／A 不能触发下层对白，Esc 不自动重听，自动播放使用可取消计时。
- 场景真正变化时同步背景、时间、HUD、角色和操作；普通读下一句不重置音乐、夜次或一次性动画。
- 主案耐心按夜、快案按当前实现的阶段恢复。浏览不扣；设计过的误问只在反馈结束后扣一次，存档或双击不能重复扣。
- 对应回归：`ordered-dialogue.test.js`、`script-presentation-parity.test.js`、`content-revision-mechanisms.test.js` 与浏览器 `script-reading`／`testimony-reading`。这些验证结构和呈现，不自动判定剧情自然。

## 本轮共性回归边界

- 顺序依赖和页面呈现分开：回放每屏完整原句及“询问这句／不询问”，问答结束后回到原句，不连续自动暴露下一条问题。序列 ID 与完成前缀仍须正确。
- 回放到末句后显示明确结束页，不自动绕回首句。玩家可返回查看或保存退出；必要问答完成后正常推进。验证必须包含全段不询问、返回上一句、中途回答后回原句及结束页读档，不能只测自动寻找正确选项的路径。
- DOM 收集只认对白所属容器，嵌套 `.call-dialogue` 不重复提取同一句；“这件先记下”等瞬时反馈有明确清除时机，换句、换屏和取消计时后不能残留。
- 材料长表与反馈分区。`materialRows` 支持点击账单发问；重点流水使用 `transactionCards / focusRowIds`，原表可另行查看。反馈不得将主对白挤出视口。
- 时间线须按实际 `correctOrder` 排对才能继续，存档恢复也重验。跨夜一次性进度如 `night2TransitionSeen` 独立保存，背景、顶部夜次、标题、对白和按钮同步更新。
- PC 主验收视口见 QA；检查边界、遮挡、截图和真实点击，不能用 DOM visible 代替。共享布局改变后覆盖普通对白、逐句回放、材料反馈和转场；最终布局变动后旧截图不能充当新版本通过记录。
