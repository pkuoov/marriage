# 案一：翻往期账页与闺蜜补图分支检查

模式：只检查、记录，不修改正式台词、数值或运行逻辑。依据为案件 JSON、幕间与回拨代码，并调用现有纯函数核对分支结果；未操作用户正在试玩的浏览器。

## 两条分支实际做了什么

| 项目 | 先翻往期账页 | 回闺蜜私信 |
| --- | --- | --- |
| 内容 | 五月、六月 8 日各入账一万，七月同日中断 | 纪念日晚餐朋友圈、闺蜜删掉的起哄评论，以及探店设备补话 |
| 主线用途 | 追男方工资之外的入账，以及这笔钱中断与周转压力的关系 | 追女方主动展示、接受排场与设备，拆她只讲男方花钱的版本 |
| 操作 | 圈账页中的关键项 | 圈补图关键项，再选择怎样回复闺蜜 |
| 后续结果 | 带回“往期账页”，增加相应回拨开场 | 带回“闺蜜删掉的那条评论”，增加相应回拨开场；回复还会改变来电人回拨态度 |
| 共用流程 | 两项都耗时 1，幕间只能完成一项；随后进入相同白天调查，再进入相同第二夜主干 | 同左 |

两条路线不是不同结局，也没有各自独占的第二夜长段。回拨时还可选白天获得的其他开场；若不选幕间带回的这一项，它对应的问答就不会播放。翻账路线的信息还与周会计的时间线、后台流水重复。现有选择的持续剧情影响偏弱。

## 查出的具体问题

1. **账页混有旧稿。** 正确选项的 `contradiction` 仍写“七月贷款到账后”，当前借款材料与男方留言均为三月。错误选项谈“交往之前的同款消费”，反馈甚至认定“这几笔的时候他还不认识她”，而当前板面只有当年五月到七月的入账行，未展示交往前的消费。作者设定确有旧消费，不代表可以拿未展示的账页当玩家这次选错的理由。
2. **翻账揭出规律，却没有形成有效追问。** 已有“我不敢猜是谁转的”等兜底句，回拨只得到“不知道，他不肯说”。合理的下一步应追男方怎样解释每月这笔钱、是否依赖它维持给付，而不是在不知道付款人身份时停止。具体隐藏付款关系尚未定，不应为了补分支就填一个人名。
3. **闺蜜补图没有继续追来电人的诉求。** 评论给了她主动展示与受益的线索，回拨却让她先自行说“脸有点烫”“那场面，我也撑过”，主播又迅速说与转八万不是一回事。支线止于认领体面与免责，没问她当时希望别人看见什么、为何第一夜不提自己受益、现在想从主播这里拿走哪一句话。后续适合接她的否认或反咬，不继续增加自我反省。
4. **回复闺蜜，直接改变来电人态度，缺桥。** `你当时起哄也算观众` 写入 defensive，第二夜来电人便说“我差点不打回来……你要是也觉得是我贪体面”。`直播里先不提你` 则写入 open。中间没有演出闺蜜如何转达、来电人如何知道这次回复，变化是数值直接连到了人物情绪。
5. **翻账完成得太快。** 圈选事件立即调用 `completeInterludeAction`，底层清空 `activeActionId`，再渲染调查台。结果页虽然写有返回按钮，但首次圈选就离开了材料页，缺少“看完结果，再主动继续”的停顿。此为代码路径确认；不把它直接认定为用户此前所述第一夜收尾跳页的唯一原因。
6. **闺蜜回复也缺少实际回应。** 两个回复按钮没有各自的闺蜜答话，选择后只留下通用反馈“这句回出去了”，随后行动完成。玩家不易感受到自己选了什么态度、对关系有什么影响。

## 修改方向，尚未执行

用户后续确定采用简化方案：两项都可以做，取消这一段的二选一、耗时和行动次数限制，不增加行动力额度。两份结果统一进入后续连线，用简洁的固定过桥接回主线，减少可选开场造成的重复和遗漏。具体先后顺序在统一改稿时按因果衔接确定。本条优先于下文保留互斥分支的备选建议；目前仍只记录，未接入。

保留两条调查角度：一条追男方资金，一条追女方说辞。两条都要留下能带回第二夜的具体问题和不同的第一轮攻防，再汇入供养关系主线。无需强行分裂主案结局，但不能只有换一句开场。

如果仍然互斥，就让每条都交付有分量的独有追问与反应，且被选中的调查结果在回拨必有回收；如果只是补充材料，则可合并成短查，不必用“只够做一件”制造现在这种差别不大的取舍。先修时间线残留、反馈停留和情绪来源，再写对白。
