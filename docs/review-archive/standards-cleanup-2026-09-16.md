# 标准清理与人工修改归纳 · 2026-09-16

本轮已修改标准源文件、相关技能／文档入口与校验；已按新标准审查剩余三主案及全部三快案。没有修改案件 JSON、游戏运行时或用户存档。六案正文和流程改稿另列待办。

## 现行规则归属

[当前项目方向](../../project-skills/case-scriptwriting/references/current-project-direction.md)维护 S1–S8：集中问询、本段重问、材料先收到再使用、人物提供信息的动机、已知事实不重新揭露、人对人的口语、直接材料操作与自然收尾。

这些来自最近案一人工试玩修改，既包含用户指定句子的记录，也明确了推广边界：男友不上麦、匿名人发两年前同店朋友圈、先问酒水是案一具体决定；通用要求是来源可信、问询有顺序、对方直接回应有渠道、没有重复循环。资料案的双人连麦和口播快案的单主播仍成立。

## 直接替换的旧标准

| 旧要求／冲突 | 处理后的规则与入口 |
| --- | --- |
| 案一集中问询，但总则仍命令每句问后回放 | 项目方向、编写 skill、流程 skill、运行时接入、主案总纲、QA、试玩模板统一为集中问询；旧实现列为待迁移 |
| 填完整多层伪装链、每层必须受压升级 | 主线账本压成按需的来源／问题／回答／下一步记录；推理参考不再要求每份证据藏另一层、每案双方有错 |
| 随机周目、永久属性成长、固定时长作为游戏宗旨 | 重写游戏宗旨，以当前剧情推理与集中问询为准；原稿归档 |
| 每案最终三句原话、事实池最低条数、满格深问 | Schema 区分兼容字段和玩家流程；取消创作配额与必需深问，保留旧消费者必要的数据类型和有效引用 |
| 来电快案整段重听、逐句循环、耗尽后观众裁判 | 快案规范改为本段问清推进，误问本段重问；不追加弹幕；旧状态机尚待迁移 |
| 快案一生育例子必须成为对质，结尾必须两轮长评 | 纠正为当前普通交流；必要问题放前面，结尾自然结束，不要求复盘页数 |
| 所有案型只能单人，另一方只能由咨询者转述 | 来源说明和 Schema 改为按本案通话方式及真实收件渠道，允许直接后台回应或已配置双人连麦 |
| 旧主线审计仍称“共同改稿依据” | 四份主线旧审计及 8 月对白审计退出现行正文，保留明确历史入口；AI 问答旧方案标为未来提案、旧流程失效 |

同步更新编剧工作流、标准索引、文档首页、专项技能与审查模板。原文件保存在[旧标准归档](standards-before-2026-09-16/README.md)，不在原命令后继续叠相反命令。

## 校验清理

修改 `scripts/verify-pack.js`、`scripts/verify-logic.js`、`scripts/verify-narrative-flow.js`，并补充 `scripts/tests/authoring-policy.test.js`。

- 移除每案最低材料／回流数、最低 2600 字、三条原话候选、事实池六条与已知至少两条等配额。内部事实栏可空；仍启用旧题目时，实际素材须覆盖配置题量。
- 不再要求满格深问；兼容 `deepFollowup` 字段可空，若配置问答仍检查完整性与来源。取消为了扩来源强塞回流、强塞噪声选项的要求。
- 证词墙按已配置段落校验，不强制每案一墙、恰好两幕、固定证词数量、隐藏句配额或两次尝试。保留可播放内容、有效目标、材料来源、兼容首幕投影与 ID 检查。
- 不再强制所有案件维护固定阶段顺序的多层伪装链，取消每层必须改变说法、改变建议及固定改口词。保留已有作者记录的类型／ID；自由说明文字不是引用 Schema，实际结构化来源在消费者处验证。
- 去掉锁定职场案“名目是主管让我填”的旧断言，该句已在本轮 W1 报告中列为承接问题。其他具体案例回归仍描述现有内容，后续改稿须同步对应测试，不能把旧案例字句升格为文学规则。

校验变宽只取消过时创作要求，未让缺问句、缺回答、无来源后台消息或错误引用自动通过。新增回归覆盖“无深问／无额外材料／无回流可成立”，同时验证配置了不完整问答或无来源消息仍报错。
