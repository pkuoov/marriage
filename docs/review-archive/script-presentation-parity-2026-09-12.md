# 台本与实机呈现偏差复核 · 2026-09-12

本次对照四案 JSON 真源、生成台本、实际渲染代码及隔离浏览器中的对白。源稿的剧情事实未改；修复的是取稿、编排和回看路径。

## 确认并修复

| 偏差 | 原因与修复 |
| --- | --- |
| 导演稿漏掉中间接话，人物似乎突然承认或突然跳话题 | 导演稿优先读 `answer`，游戏优先读多人物 `lines`。当前可玩场景有 19 个正确选项使用多人物回答。导演稿、连续稿与实机回答现在共用 `answerDialogueLines`，有多人物对白时不再播备用短答。 |
| 游戏“上一问”与刚才实际听见的回答不同 | 关键问题的回看只取备用短答，并强行标成咨询者。现在保留实际选中回答中的人物及接话顺序。 |
| 连续稿把第一段问完才写第二段，实机却先播放两段陈述 | 生成器逐个遍历场景后立刻输出该场问答。现在读取运行时 `statementStages`，先写完整陈述，再按代表路线进入回放追问。四案首个阶段均修正。 |
| 白天看完材料直接进入第二夜主线，漏掉材料追问 | 线性调查遍历日间场景时丢掉了旧路线中的材料选择。现在明确列出每案所标行，使用运行时 `earnedDocumentQuestionsFor` 得到回拨后可问内容，本条代表路线共补回 12 组问答。 |
| 台本无条件写出第三案材料触发的现场反应 | 生成器只检查场景序号，不检查材料触发条件。现在用运行时 `liveCounterBeatTriggerMet`，以本路线实际标注判定。 |
| 必经时间线排序的结果从台本消失 | 连续稿、纯故事稿和导演稿只收日间正文／普通选项，漏掉 `timelineSort`。连续稿补正确排序及结果，分支汇编同时收正确和错误反馈。 |

代表路线的材料标注：第一案 `r13/r14/r15`；第二案 `q01/q03/q05`；第三案 `p04/p06/p07`；第四案 `m03/m05`。白天尚未收到的材料不能进入这份路线配置，重复行、缺失行、超出标注上限均拒绝生成。

## 阅读方式与覆盖边界

连续故事台本是一条明确材料选择的代表路线。回放不逐字抄写已听过的陈述，也不列每次翻页；它不是逐帧录像。纯故事稿／全量稿并列展示分支，不能把相邻的两个替代回答当成同一段对话来修改。

这次浏览器核对覆盖四案首轮陈述与回答、八幕证词墙。其余普通／错误选项的每一种组合未逐条人工重走；后续发现具体句子异常时，仍应带上问题 ID、已选材料与前后实际对白。通过结构校验不等于所有人物对白均已完成语义审稿。
