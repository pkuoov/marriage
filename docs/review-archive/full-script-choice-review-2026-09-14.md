## P1：先修的信息与选项错误

### S01｜存款证明：男方尚未进直播间，就在证词墙错误反馈中插话

- 定位：[03-profile.json](../../content/packs/steam-demo-01/cases/03-profile.json)，`profile-family-chat-origin.testimonyWall.acts[1].missFeedback`，约 1252／1256 行；后续 `profile-gift-mic-request`、`profile-mediation-consent`，约 2552–2670 行。
- 复现：进入第二幕证词墙，第二次错误出示材料或原话。反馈分别是“男方问：你现在是在问她，还是在问我？”和“男方插话：这句我听见了，让她接着说。”
- 问题：男方送礼、申请连麦及“我才进来的”发生在这个场景完成之后，第二路麦克风也要之后才接通。不是人物隐瞒，而是出场顺序错了。
- 处理方向：当前阶段的失败反馈由已经在场的人承接；需要男方参与的交锋放到实际接入后。复验必须覆盖第二次失败，不能只看正确路线。消费者为 `testimonyWallScreens.js:300` 的 `decisiveMissReaction`，确实按尝试次数取这两条。

### S02｜理发店：跳过可选追问，主播仍提前知道合同未给

- 定位：[02-tony.json](../../content/packs/steam-demo-01/cases/02-tony.json)，`tony-caller-benefits.casualQuestions[0..1]`，1114／1120 行；`tony-comment-benefit-blowup.choices`，2435 行。
- 复现：第二夜只完成 `tony-caller-benefits` 的必问“谁先提出代投”，不问转钱前看没看合同、转完后拿到什么；继续弹幕反应的连续对白。
- 问题：主播仍必经“帮自己人，帮到合同都不给你看了？”此前必问只说明十二万如何并入 Tony 账户；周的补图也只能说明另一笔钱的情况。她自己没有产品全名、合同和回单，放在可跳过的追问里，之后证词墙才进一步展开。
- 处理方向：让合同缺失先通过必经对白进入共同知识，或按已询问状态改变接法。不能让可选问答暗中成为必经台词的前提。

### S03｜快案：只选“询问这句”，却按没有说出口的问题扣耐心

- 定位：[02-one-missed-message.json](../../content/packs/steam-demo-01/quick-cases/02-one-missed-message.json)，`founder-busy`、`family-level`、`age-gap`，439–467 行；[quickDetectiveModel.js](../../src/runtime/quickDetectiveModel.js):82、[quickDetectiveView.js](../../src/ui/quickDetectiveView.js):209、375。
- 复现：对“他三十五，自己开公司，是婚恋机构介绍的。”点“询问这句”。没有主播问句，直接出现“我打来不是替他解释工作的”，耐心从 4 降到 3。再问家庭与年龄原句，依次降到 2、1。
- 问题：内部选项写的是“创业者是不是都没时间听歌”“九岁年龄差是不是根本问题”，但玩家没有选择或听到这些论断。年龄原句还同时包含学历，玩家想问哪一项也没有得到具体化；反馈却认定他已把年龄当成原因。失败不是输在已经提出的问法上。
- 处理方向：失败路线也要先说出实际问题，再让人物回应；判罚须对应这个可感知的提问行为。无锚点句子的通用失败反馈也要沿此检查。不要靠恢复旧的多选标签替代当前逐句询问要求。
- 验证：已用真实案件 JSON 调用 `applyQuickStatementLineSelection` 复现上述三次状态变化，非仅根据选项名字推断。

## P2：剧情承接、材料与提问设计

### S04｜存款证明：学校材料检视提前借用了母亲的推论

- 定位：[03-profile.json](../../content/packs/steam-demo-01/cases/03-profile.json)，`profile-mba-gap:option:0`，1847 行；下一场 `profile-caller-repeats-label.afterVersion`。
- 前后文：目前先说“自己拿二十三万八读书，还能没积蓄”的是来电人。材料正确反馈却直接问“你妈凭什么认定他现在还有这笔钱？”母亲拿学费推家底、据此加彩礼的原话到下一场才说。
- 问题：已知母亲看过工资卡，不能自动补成她已经用学费作了同一推论。问句把后文信息提前当成了共同前提。
- 处理方向：这一屏先追来电人自己的判断；等母亲原话出现后再追传播与加价过程，或先补一句自然转述。

### S05｜信用卡：餐厅消费已经层层问完，又回到同一个起点

- 定位：[01-credit.json](../../content/packs/steam-demo-01/cases/01-credit.json)，`credit-anniversary-agency.questionSequence` 与 `credit-anniversary-footprint:option:0`，约 969 行、2247 行。
- 前后文：先问平时是否挑这个价位、谁选店付钱、探店有没有合作收入，准备接设备分期；随后材料页又问“看来你也是常去这家餐厅了，之前消费也不低吧”，她又答“也不是总去这家，别家也去”。
- 问题：补图材料自己已经列出了前面问出的日常消费结论，却仍把它作为待发现问题；对白的话题刚往设备走又退回餐厅，形成用户之前反馈的长问答与重复感。
- 处理方向：保留“纪念日特殊消费 → 日常高消费 → 谁负担 → 收入”的递进。补图若只复核定位就明确复核作用；若需要新追问，应落在尚未交代的消费或付款信息上，不再从来过几次重启。

- 处理方向：先确定谁负责首次披露、谁负责复核原页／追改变后的说法，再按是否已问改变后续接法。不能一概删复问：职场第二幕追“有没有实际外部服务”确实比第一夜分账新增了关键内容，应保留。

### S07｜信用卡：最后的“深问”再次验证已经明说的条件

- 定位：[01-credit.json](../../content/packs/steam-demo-01/cases/01-credit.json)，第二幕 `decisivePresent.callerLine`，1832 行；`deepFollowup.question`，2491 行；`careChoices[0]`，2554 行。
- 前后文：她已经说“以后还能照常给，我们当然可以再谈……给不了……我还不能走了？”后面又问“如果他明天又能每月给你一万七千五……还非分不可吗？”收尾还问“你把这通也发给他了？”，而之前她已明确男友正在听。
- 问题：这里可以继续争辩责任，但两个问句都重问已知状态，没有承接她刚做出的选择，收尾显得忘记了前文。
- 处理方向：从已答的条件继续追她打算如何面对余额、承诺或下一步，允许她顶回去；已确认在听的事实直接承接，不再询问是否转发。

### S08｜职场：供应商工作语音未出场，主播已用“那条”索要

- 定位：[04-workplace.json](../../content/packs/steam-demo-01/cases/04-workplace.json)，白天供应商场景，2330 行。
- 前后文：供应商先讲三栏表及各岗位返费；主播突然说“三栏表和那条工作语音一起发给我”。对方随后才开始提供语音内容。
- 问题：此前没有人说手里有这条语音。“那条”假定双方已经知道具体材料，来源出现得晚于索取。
- 处理方向：先由供应商提到工作群语音，或主播先问当时怎样通知、有没有保留。不要把内部 `access` 说明当成玩家已经听过的铺垫。

### S09｜职场：结尾预算材料把调查退回早已解决的问题

- 定位：[04-workplace.json](../../content/packs/steam-demo-01/cases/04-workplace.json)，`work-assistant-flow-sample`，1486 行；连续稿“后台收到部门预算页”约 1223 行。
- 前后文：玩家已经完成费用草单与两幕证词墙，确认一万二没有对应外部服务；深问后，预算通知又问“八万预算能不能直接当作个人奖金”，反馈“先看实际费用单和对应服务”。
- 问题：这不是确认未付款或追新回执，而是要求玩家回头完成刚完成的证据步骤。通知为什么此刻才到也只写了“第一夜问到多报分成后”，未解释这个延迟。
- 处理方向：把预算通知放到第一次区分额度与个人分成的位置；若保留结尾，则围绕新回执或付款变化提问，不能重置查证进度。

### S10｜理发店：Tony 私人收款、门店发函及收函人混在一起

- 定位：[02-tony.json](../../content/packs/steam-demo-01/cases/02-tony.json)，`tony-manager-training-note.material`，1832 行；`tony-business-letter`，2454 行起；`stageJudgement`，1976 行。
- 前后文：店长明确说店里只做美发、没让员工代收这类钱，Tony 的私人行为问本人。之后老方说“店家商务函到平台了”，主播接“十二万他收了……寄商务函倒挺快”“这店服务还真周到”，来电人又说“别光给我发函”。
- 问题：可以怀疑门店借函施压，但现稿没有函的具体内容，也没有交代门店替 Tony 回应收款；收函方还从平台跳成来电人。对白把尚待追问的关联直接合并成同一行动主体。
- 处理方向：明确函由谁发、给谁、要求什么。主播可以追门店为什么替员工挡问，或讽刺先保声誉，但须让关联在对话中成立。

### S11｜存款证明：饭店从“还没订”直接变成有定金可损失

- 定位：[03-profile.json](../../content/packs/steam-demo-01/cases/03-profile.json)，`openingDialogue`，413 行；`profile-weekend-dinner-cancelled`，2705 行附近。
- 前后文：第一夜“饭店还没订”，第二夜男方说“周末包间的定金我来认”。两夜之间没有谁订了饭店、为何争执中仍先订的交代。
- 问题：时间上并非不可能，但这里新增了支出和男方承担损失的具体行为，缺少状态变化；玩家容易理解为前后改稿没接上。
- 处理方向：补实际订位者、订位时间的一句承接；或让取消只涉及约定，不凭空新增已付定金。

### S12｜快案《什么都不图》：跨轮“这个”指回了错误话题

- 定位：[01-no-conditions.json](../../content/packs/steam-demo-01/quick-cases/01-no-conditions.json)，首轮必经 `sales-soft-talk` 收尾、下一轮 `birth-father.host`，377／261 行。
- 前后文：追问结束是“下班找个对象，还得让我哄？我一天都够累了”；下一轮主播说“你为什么把这个看得这么重？”，她却讲父亲受伤后母亲离开。
- 问题：这句原本接最初陈述的“遇事别转身就跑”，加入必经追问后，直接前句变成不愿哄人，代词指向丢失。
- 处理方向：新一轮明确接回“家里遇事别离开”，再讲家庭经历。所有跨轮开头的“这个／刚才／所以”都应以实际插入追问后的前句核对。

### S13｜快案：原句锚点不同，却跳进同一段不对应的首问

- 定位：快案一 `actual-standard` → `hidden-standards`，339／479 行；快案二 `flower-request` → `care-or-display`，415 行起。
- 复现一：问候选男生那句“先别急吧”，首问却是“你前面说另一个嫌你脾气不好。那个人跟你吵过钱吗？”
- 复现二：问“顺口问他能不能也送我一束”，首问却是照片旁边的包谁买的，与另一个“朋友羡慕”锚点共用整段追问。
- 问题：这两段可以最终通往共同主题，但没有先承接玩家选的那句。内部标签描述的问题与实际问题也不同，玩家无法建立“我问了什么，所以她补了什么”的因果。
- 处理方向：按原句写不同的第一问和必要回应，再汇入共用段落；不需要为此增加无意义的整条分支。快案二已交代截图发到后台，不能把此项误写为“完全没有照片来源”。

### S14｜快案《那晚没回消息》：收尾突然引入“男方说话重”

- 定位：[02-one-missed-message.json](../../content/packs/steam-demo-01/quick-cases/02-one-missed-message.json)，`ending.summaryPages[0].lines`，718 行。
- 前后文：已提供的男方原话主要是问喝得怎样、何时回家；之后是追问与冷淡。结尾来电人要求“他好歹也得说句自己话重了”，主播直接把话题转为她要赢、要对方哄。
- 问题：这可以是来电人又一次省略，也可以是新增委屈，当前却没有追那句重话是什么，无法判断她又改写了什么。矛盾点刚出现就被结论盖掉。
- 处理方向：让她给一句原话，或表现她拿不出／避开具体内容，再继续争辩。无需替她认定对方没说重话，也不要求她承认自己编造。

### S15｜快案《写给女演员的长文》：公开转述少算了一层

- 定位：[03-labeled-fiction.json](../../content/packs/steam-demo-01/quick-cases/03-labeled-fiction.json)，`mediation-retelling.source`，381 行；`mediation-authorization.lines[1]`，668 行。
- 前后文：材料是“男方称，中间人来传话……”。点评变成“现在只有中间人说是她的意思”。
- 问题：现有来源是男方对中间人说法的再转述，没有独立的中间人原话。点评虽提醒缺女方授权，却不小心提升了中间人这层的可验证程度。
- 处理方向：保留“男方说中间人如何转述”的来源层级，再讨论有没有委托与本人原话。角色可以提出推断，但不能悄悄缩短来源链。

### S16｜共性：错误材料反馈直接报答案，或提前替人物承认核心加工

- 定位：信用卡 `credit-after-layoff-spend:option:0`，2196 行；存款证明 `profile-mba-gap:option:2`，1864 行。
- 信用卡：选择四万共同消费与五千男装，反馈直接说“还没说清的是剩下那三万五”，几乎逐字给出另一个正确选项。
- 存款证明：错选“介绍人有没有夸张”，来电人直接承认“名校毕业和有钱，是我们家自己接出来的”；下一场才原定逐句问她怎样加工介绍人的说法。

## 共性修订顺序与验收路径

1. **先修信息顺序与判罚**：S01–S04、S10、S15。给每个必经问句核一个前提：是哪位已在场的人、通过哪个已播放节点让主播知道的。正确路线、跳过可选问题路线、连续两次失败分别走。
2. **再合并首次披露与复核**：S05–S09、S16。材料问答与主线共用事实进度；复核应指明复核对象，改口应带来可辨认的范围变化，不能把“每句都要新事实”立成新配额。
3. **补选句与对白的接法**：S12–S14。每个锚点至少检查“选中原句 → 实际首问 → 回应 → 回原句／下一轮”这条链；合流可以共享中后段，首问不能答非所问。
4. **同步状态变化与阅读稿**：S11、S17。订位、接麦、材料到达等变化进入实际台词或场面，再生成审稿文件，不能手改生成稿假装问题已修。
5. 修订完成后做 PC 实际回归，尤其是材料 → 追问 → 回放、连续错误反馈、男方接麦和结尾的多段切换；本轮没有给这些 UI 标注已验收。
