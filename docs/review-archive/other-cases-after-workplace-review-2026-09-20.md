# 用第二案复盘重新审读其余案件

日期：2026-09-20。审读基线：`513a45404c45fad81c991990e726dae9afa114a0`。

初审只记录问题与建议，未修改正文；用户随后要求继续修改，同日实施结果见文末。依据《第二案：试玩记录统一修改与根因复盘》和《案件时间线与尾声收口》，重新审读信用卡、彩礼、Tony 三个主案、三个独立快案，以及序章相关接缝。第二案复盘里“第三案后进入第七晚公开回访”属于已被新日历取代的历史安排，不作为本轮标准。

方法是沿现行连续台本核对 JSON 与播放消费者，检查每个节点之前玩家已经听到什么；另用隔离 Playwright 会话定点核实两处 UI 疑点。不是新一轮从头无先验盲玩，也没有宣称穷尽全部可选路线。

## 总体判断

三个主案的主要揭露方向仍然成立：信用卡从周转理由推进到代存约定与钱已花掉；彩礼从学校误会推进到付款条件和双方出资；Tony 从半张名单推进到主动代投与缺失的成交凭证。不需要推倒重写，也不需要再加知情人。

但第二案暴露的问题确实还在别处：已经知道的事实再次当成新揭露；旁白提前替人物解释来意；旧对白被当成现行原话引用；相邻问答只改了一半；材料 UI 比人物先知道答案。另有一整套维护文档仍记录旧时间线和旧知识状态。

## 优先处理

### 1. P1｜彩礼案：已经知道是工资账户，后面却追究“没说清这是工资账户”

定位：`content/packs/steam-demo-01/cases/03-profile.json:362`、`:398`、`:2348`、`:1411`、`:1416`。

第一夜，女方明确说“他只发来一份工资账户流水”，并复述自己问“只有这一张”，男方答“工资卡最清楚”，她接着问其他账户、男方没答。到这里，双方及玩家都知道这份材料的范围。

白天表姐却把“我提醒他说明这只是工资账户，他没带那句话”作为新消息；第二夜主播据此问“为什么发的时候不说清”，男方又承认“只发这一张，确实没说清楚”。这把已经明确的材料范围重新写成隐瞒，制造了一个并不成立的新揭露。

建议：保留“只愿提供工资账户、拒答其他账户、没有接受女方付款条件”的真实冲突。不要再让他承认没说明账户性质。表姐若只剩重复已知事实，应压缩或并入已有消息；如果保留家里挑选材料的过程，也只能证明挑选过程，不能证明女方不知道范围。不能为了给表姐增加作用，再编出隐藏余额。

### 2. P1｜序章家庭卡：明细尚未发来，UI 已经展示核账结果（实机确认）

定位：`src/ui/screens/recapScreens.js:661`，`src/ui/prologueCafeView.js:260`，`content/packs/steam-demo-01/manifest.json:1482`。

家庭卡场景首句是男方说“近一年的明细我能下载”。后续才有主播让他发送、建群、转交周会计、询问车贷和转账备注。

但首句的实际屏幕已经完整展示：四个月前车贷结清、每月十八日固定转出、摘要“私教课时”、个人账户和户名未显示全。这不是只存在于隐藏 DOM 的内容，浏览器可见文本和截图都确认了。玩家先看到了后文要逐步问出的结果。

建议：按收到明细和读出具体内容的节点展示材料；至少收到之前不得出现。车贷和备注若承担揭露作用，应随相应交流展开，或让后文承接玩家已读到的内容。不能仅修鉴定结果卡，却把家庭卡留在原来的整页提前显示方式。

### 3. P1（维护）｜设定文档仍在输出已经废弃的时间线和玩家知识

定位：`plot/timeline.md:8`、`:10`、`:22`、`:25`、`:40`；`continuity/state.md:18`、`:26`、`:31`、`:53`、`:59`、`:68`；`story.md:21`、`:48`、`:68`。

当前运行时已经区分七月信用卡、七月职场、八月彩礼、九月最近发生的 Tony 案；序章在九月一日，新闻与鉴定分别在九月二十二日深夜、二十三日上午。上述文档却仍写现在是 2026 年、回到两年前、七月十五至二十二连续八晚。

更严重的是知识状态仍写：玩家已知沈剩一万一千六百多；鉴定与家庭卡只走其中一条；第二案仍有强制贴片代价；男方已承担取消饭局的包间定金。其中余额在现行对白中明确拒绝公开，双路线已改为顺序发生，贴片也已撤销。包间定金则不应继续作为没有现行动作支撑的既成事实。

这不是当前屏幕必然已经出错，而是后续改稿会采用的“不可重置事实”本身不可靠。建议先与 `manifest.storyCalendar` 和现行实际路线对齐，分开作者知道、人物知道、玩家已知；删除退役动作的现行事实身份。不要为了让正文符合旧文档，把已修内容写回去。历史复盘保留历史说明即可，不必改写成好像从未出现过旧方案。

## 其余需要收口的内容

### 4. P2｜第三、四案仍由旁白提前解释第三方动机

定位：`03-profile.json:2318`、`:2328`、`:2357`；`02-tony.json:1793`、`:2296`、`:2345`。均在 `content/packs/steam-demo-01/cases/` 下。

典型句子包括介绍人“不愿独自承担传错话的指责”、表姐“为澄清自己的参与”“免得最后成了她教表弟瞒人”、朋友“怕被算成劝她买的人”。这些不只是作者字段：`overnightScreens.js:310`、`:366` 会把 `body.text` 和 `sourceNote` 展示出来，连续台本也收录了。

人物来源其实已有：来电人转连线片段、男方拉表姐私聊、小何联系朋友、店长主动约见。后面的抱怨和反驳也已经足够表达各自立场。旁白再把目的概括一遍，等于先给玩家一份人物解读，再让人物重复证明它。

建议只保留牵线、约见、发材料、接通语音等动作；将必要情绪留在抱怨和接话中。表姐的“你去问他，我不替他答”（`03-profile.json:2353`）也重复了用户已经指出的机械声明，可收成“那你当面问他”。不需要把人物写成没有私心，也不应删除有具体内容的真实拒答。

### 5. P2｜Tony 材料卡引用了当前路线没有说过的“原话”

定位：`02-tony.json:1484`；`src/ui/screens/testimonyWallScreens.js:80`、`:224`。

“他只给了提交页”场景的材料卡写着：“转钱以前，小姐妹提过高息档一百万起投，我只当听个热闹。”来源是“第一段证词 02”。这句话仍保留在旧 `testimonyWall.statements` 中，但现行路径有 `inquiry` 时直接进入集中问询，不播放那套证词墙。

玩家实际听过第一夜的“利息高／不是我手里那点钱能买”，白天朋友说“一百万起”，第二夜来电人说“我知道不够一百万”。这些可以支持她提前知道门槛，却不能拼成一条带引号的本人原话，更不能要求玩家记得没有播出的“证词 02”。

建议改为引用已经播放的本人原句，或标为朋友白天语音并准确引用。材料的来源应是玩家听到的人与场景，不是旧玩法内部编号。

### 6. P2｜其他问法中仍有只改问题、没改回答的接缝

定位：`01-credit.json:1563`、`:1568`；`02-tony.json:1373`、`:1378`。

- 信用卡问“他让你少花点，你回过他一句好、我少花没有”，答“回过敷衍。那会儿没有把钱转回去”。前半句本身不成口语，后半句又突然跳去未问的返款。可先答清当时是否只是随口答应，返款留给有铺垫的追问。
- Tony 问“有没有把‘帮我买’和转账发在一起”，答“没人叫我空着”。这是在回答另一道关于备注为何空白的问题，后半句也没有明确回答当前问的聊天先后。应让回答承接当前问题，或写出她为什么刻意避开，而不是保留旧问题的答句。

两处都出现在当前问询选项的 `lines` 中，不能因默认正确路线通顺就略过。修时连读这一问、这一答及返回当前问题的提示，不只替换一个词。

### 7. P2｜Tony 第一夜已经承认裁图目的，下一段又重问

定位：`02-tony.json:805`、`:574`；连续台本中“金额那几列你自己认了”前后。

她已经说裁掉金额和产品，是想先谈他怎么对自己，怕大家先问为什么转钱。主播接着说“约会是不是真的，下一句再说”。下一段却又问“你把金额裁掉，是怕人看见这张表在记钱，还是真要把半张名单说成养鱼”。

这不是新证据带来的加压，而是已经回答的动机在段落边界重新来一次，也没有兑现刚才预告的话题。后面关于“你们谈过恋爱，能说明其他人也是女朋友吗”的问法才真正往前推进。

建议入口直接承接她声称的约会与关系，再追她凭什么给其他女客定身份，之后推进高息来处。保留她嘴硬，不再把裁图当作需要重新认一次的秘密。

### 8. P3｜快案二收尾有口气和落点问题，但不是必须强行解决关系

定位：`content/packs/steam-demo-01/quick-cases/02-one-missed-message.json:631`、`:635`、`:639`。

来电人要一条不显得求人、又要求男方先道歉的消息；主播回“这道歉我不替你圆”，来电人“那我再想想吧”。“这道歉”指代不清：她此刻要求的是男方道歉，并没有请主播替自己道歉。主播的机械拒绝也没有具体接住她的要求。

建议先明确指出她要求对方先道歉、自己又不愿把经过说全的冲突，再让她给出当前决定。可以暂不联系，也可以仍坚持自己的条件，不必强迫她认错或和好。“再想想”并非逻辑错误，因此这一项低于前面的事实和播放顺序问题。

## 排除的疑点与保留项

- **快案二朋友圈汇总没有在开头剧透。** 静态模板确实一次插入全部 `materialRows`，但 `src/ui/screens/quickDetectiveScreens.js:247` 的播放控制会隐藏材料，直到该段末页。隔离浏览器停在“近两个月的动态还能找着吗”时，可见文本没有材料，材料节点带 `hidden`、`display:none`、尺寸为零。不将这处写成待修漏洞。
- 第一案拒绝报余额，第四案十二万是否实际成交仍未知，都是已经表达出的拒答或凭证缺口；不能为了“完整结尾”补成明确余额、成交或损失。
- 介绍人、表姐、朋友、公开客服、店长已有接触渠道。本轮主要问题是目的被旁白抢先解释、个别角色传递重复信息，不宜统称所有第三方都是空降 NPC。
- 快案一拒绝向陌生来电人推荐对象，直接回应了她的请求；不因出现拒绝背书就一概删去。快案三是主播读文点评，不能把主播的推断全部当作旁白越界。
- 两份较新的复盘优先于旧复盘里已经撤销的贴片、连续八晚和回访位置；验收应跟现行内容，不跟历史记录机械对齐。

## 建议修改顺序与验收

先修彩礼案的假揭露、序章材料展示时机，并同步现行时间与知识状态；再处理人物来源旁白、错误原话来源、问答接缝和重复追问，最后看快案二收尾是否仍显得悬空。

验收重点不是“有没有来源字段”，而是：玩家听过没有、人物此刻知道没有、画面先显示了没有，以及本段结束后事实有没有真正向前走。UI 修复需复核首入和中途读档；内容改动需重生成台本，再连读相邻问答。报告本身不涉及代码改动，本轮未重跑全量构建，也未把定点测试计为完整试玩。
