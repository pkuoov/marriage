## 总原则

先问这句话是否提供了尚未交代的来源、允许查看/公开的范围、知识限制或人物关系。只有本场已充分表达且再次出现没有作用的部分，才按冗余处理。

换说话人不能改变谁知情、谁授权、谁在场；删去提醒也不能让下一问越过已经约定的范围。禁止把未知写成已知、把材料解读升级成判决。

# 单 1｜14 条 access 与场景表达逐场去重

## 先区分两条渲染路径

- [overnightScreens.js](../../src/ui/screens/overnightScreens.js) 的普通场景渲染 `body.access`、`body.text`、`body.beats` 等内容。来源提示和人物对白可能重复，可以比较后精简。
- [overnightDocumentScreens.js](../../src/ui/screens/overnightDocumentScreens.js) 的 document 场景只渲染 access 与 documentViewer，不读取 `body.text` 或 `body.beats`。**不能把 document 的边界搬进这些字段再删短 access，玩家会看不到搬过去的信息。**
- `build-readable-script.js` 会导出 body.text/beats，即使游戏的 document 分支不显示它们。因此连续台本里“已经有这句”不能代替运行时可见性验证。

本单选择最小改动：document 场景的必要来源和限制继续由 access 承担；普通场景才允许在现有 text/beats 中去重或重写。不为迁移提示新增 document 对白流程。

## ⚠️ 落点约束：字段不能删空

- `scripts/verify-pack.js:767`：`assertNonEmptyString(scene.body?.access, …)` —— **每个 dayScene 的 `access` 必须非空**。
- `scripts/verify-logic.js:5218`：案 3 每个 dayScene 都必须有 `access`。

**所以不许删字段、不许留空串。**
没有逐字锁不代表文本完全自由。非空只是最低结构检查，不能证明来源、限制、公开范围或人物知识没有变化。

## 边界

- **不许删 `access` 字段，不许留空。**
- 玩家必须仍能知道谁提供、怎么联系、能问/看/公开到哪一步。只保留“为什么能问”不足以证明信息没有丢失。
- 不为了消灭所有相似句式而改动已经自然、清楚的来源提示。可保留原文，交付说明原因。
- 允许修改 access，以及普通场景中承接信息所需的 body.text / body.beats 文本；不新增说话人，不改已有 speaker、cast、audioCueId、材料、选项、结果、routeAxis、earnedItem 等。document 场景仅改 access。
- 保留 `dayStageExtrasHtml` 的其它渲染。本单不顺带调整通用 observe 提示或场景布局；若发现提示与实际地点不符，单列定位和修复建议。

# 单 2｜减少弹幕与顾问对白中的重复提醒

## 复核：现有链条并非没有例外

原单列举的弹幕与主播回应示例：

```
弹幕「一万七千五按月来，我工资都没这么准」→ 主播「先别羡慕，七月那格正好空了」
弹幕「差两千开始算态度了」            → 主播「先别替截图算心情」
弹幕「第一次见追款还得先把截图取消裁剪」  → 主播「先别替截图伸冤」
```

这些句子可检查重复语气，但“先别替…”的次数不能替代逐条分类。当前 `01-credit` act2 实际是“先别羡慕”，不是“先别替…”。

已有例外：`04-workplace` act1 弹幕说公司喜欢统一、不喜欢打钱，主播接“她们这两笔也都写着待通知”；`03-profile` act1 弹幕感叹开始算钱何时到账，主播接“我也没想到”。不能按“从未接住弹幕”的错误前提强行再制造一次。

原单列举的顾问/制作人语句须读完整上下文：

```
赵律师：现在只能说风险高，你别先替人宣布拿不回。
赵律师：没合同，别先算它能不能兑。
赵律师：…都不能从这页上猜。
老方  ：别看都叫宸直，就算成同一笔。
赵律师：先别替人家发愁。
```

其中既有未知信息的范围，也有案件间资金不能混同的说明和夫妻关系对白，不能统一标成无信息的刹车。对系统口吻的评价属于本轮设计判断，不是由否定词数量直接得出的事实。

## 改法

### A. 让弹幕互动有变化，但不替玩家完成推理

路径：`sceneVersions[N].testimonyWall.acts[M].reliefBeat.{comment, hostLine}`。

先检查七个有效 reliefBeat，最多调整其中 1–2 处重复或刻意的语气，也可保留已有互动。不为达标补一条“你说对了”，更不为了让弹幕显得聪明而让主播装作没看出已知问题。

### ⚠️ 这里有条不能碰的红线

既有公平设计：**弹幕不得成为证人**——不许由弹幕先说破玩家还没查到的材料事实、缺失字段或正确答案。

除不提供新事实，还要保护玩家尚未完成的推理：材料已经见过，不代表弹幕可以提前说出正确的证据—原句组合、动机或指认答案。“拿旧图拖她”也可能是待验证的动机，不能当成天然安全的常识例子。

`testimonyWallHtml` 把 reliefBeat 放在证词列表及正式指认操作前，通常一进本幕就能看见。每条必须列出“此时已公开的事实 / 尚待玩家判断的关系 / 为什么此句不泄题”。可以认可情绪、复述已确认内容或接住玩笑；分不清则保留原句并说明。

按 scene id 和 act id 查找，保留 listenerId。若修改 act1 reliefBeat，同步 `scene.testimonyWall.reliefBeat` 的旧版镜像，避免不同入口内容漂移；act2 不覆盖 act1。不要改 `decisivePresent.hostLine`。

### B. 顾问按整段信息去重，不按数量删减

落点在 `content/packs/steam-demo-01/manifest.json` 的 `nightShell.interludes`，按 afterCaseId 和原句定位，不能在生成索引里直接改。

| afterCaseId / 原句锚点 | 必须保留的作用 | 可调整范围 |
| --- | --- | --- |
| 01-credit / “产品、合同、到期日都没看见” | 缺少具体产品资料，不能把已有兑付纠纷等同于本人的二十万拿不回；后面主播接等合同 | 如压缩，只去掉同义提醒，不删信息缺口及下一句前提 |
| 04-workplace / “别看都叫宸直” | 押金归集和前案个人认购是两件事，不能合成同一笔或补出后续用途 | 保留区分，不按“全是刹车”删除 |
| 03-profile / “那就先看持有页” | 目前只见持有页、未见合同，后接父亲承诺兑现未知 | 可压缩刚被主播重复过的金额/到期表述，不改变数值或兑现状态 |
| 03-profile / “原图先别删” | 整段说明打码课纲来源不明，不能据此推断购买课程或几名来电人相识 | 不得按首句把整段删掉；是否精简首句取决于保留原件的动作是否已交代 |
| 03-profile / “先别替人家发愁” | 后面是“第一次去我家”的夫妻经历提问，主播回答承接这句 | 允许调整开头提醒语气，保留关系提问及回应链，不能拿一段嗦面动作替掉 |

未列出的顾问台词不因配额扩改。逐处通读前后两轮，必要的段落允许全部保留。此时赵律师和老方有语音在场方式，不能凭空改成“她把汤推过来”等现场动作；已有汤和嗦面也不需要为了填空重复出现。

### C. 本单不强制新增主播误判

让主播先断言、再被事实推翻，会新增人物立场和信息揭示节拍，不是提示去重。当前已有他追问“已经兑不出来了？”等试探，疑问不等于已经下了错误判决，也不能冒充已完成的自我纠错。

本单撤销“必须犯错一次”的要求。若后续要设计这一段，应另列明确的旧判断、可用依据、反证来源、回收位置及对后续选项的影响；不能在此单里随意挑一案插入，更不能称它是塑造性格的唯一办法。
