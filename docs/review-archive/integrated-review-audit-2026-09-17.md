# 整合复查报告的二次审读

日期：2026-09-17。对象：[剧情 · 节奏 · UI 整合复查](integrated-story-rhythm-ui-review-2026-09-17.md)。本轮只审报告，不修改游戏、原报告、标准或存档。

结论：主要修改方向成立，但不宜原样作为执行指令。需纠正一项节奏硬配额、两项 UI 证据归因、一项遗漏及两项事实表述。用户要的是陈述、集中询问、情绪释放各有空间，不是给每案规定相同场次数量。

## 需要纠正的六项

### 1. P1：把节奏目标写成固定配额，可能再次削碎剧情

位置：原报告第 54、67 行。

“每案只留三次密”“每夜最多两场庭审”“夜一一次出示”把建议变成了全案共同的结构限制。它们既没有逐案论证，也与当前方向“不设段数……配额”不符。报告虽然拒绝句数配额，却仍给场次和信息峰值设了配额。按此执行，必要的第二次追问、改口或反驳可能为了满足上限被删。

建议替换为：先让玩家听懂本场诉求和完整说法，再围绕争议集中询问；关键回答之后留出抵抗、改口或行动的空间；按本案需要决定轮数。舒缓段可以有新发现，只要不在情绪峰值后紧接一长串解释。案一收播研究理财吸引力、案二用资料检验盈利说法，都是报告第 72 行认可的功能，不能同时被“收播只消化已问过的人”排除。

依据：[当前项目方向](../../project-skills/case-scriptwriting/references/current-project-direction.md) S1、S7。

### 2. P2：U4 的空框截图不能证明“错问重选后”出错

位置：原报告第 109—111 行及第 155 行。

职场第二幕截图确实有空白框；但截图调用在 `scripts/smoke-browser-replay.js:3256`，选择错误问句发生在第 3259 行。它不是本幕错问后重选的截图。当前 `testimonyWallScreens.js:223` 在已听过开场时使用 `data-inquiry-context` 简短提示，并不再次生成开场对白框。

因此，“错问不重播导致留下空框”的因果未成立。若只修改重试分支，可能完全修不到截图里的问题。应保留“问询页出现空框”这一观察，分别验证首次进入、文字播放完成、重试、读档四个状态后再定位原因。重选时是否应保留可查原话，可以另列可用性建议，不能借这张截图冒充已证实的故障原因。

证据：[职场第二幕截图](../../output/playwright/simple-mechanics/04-workplace-act2-1280.png)、[截图与点击顺序](../../scripts/smoke-browser-replay.js)、[问询页面分支](../../src/ui/screens/testimonyWallScreens.js)。

### 3. P2：U2/U3 把相似现象写成了用户原场景已经确诊

位置：原报告第 102、106、132 行。

`030.png` 能证明有一页空景加“继续”，不能证明按钮遮住正在说的台词。绝对定位与较高层级也只能说明可能覆盖，不能单独证明发生了遮挡。案一问询截图能证明“接着问”角标与“咨询者”名牌重叠，却不能据此认定用户第二夜连麦中的遮挡“就是这个布局”；报告自己也承认没有走到该场景。

建议拆开状态：无内容确认页已见、角标名牌重叠已见、用户所述对话进行中的挡字仍待复现。删除确认页与调整角标可各自修，但不能将它们通过验收等同于笔记 1/7 全部解决。

证据：[空景继续页](../../output/ui-walk/shots/030.png)、[案一第二幕角标重叠](../../output/playwright/simple-mechanics/01-credit-act2-1280.png)。

### 4. P2：整合时漏掉 G-05，执行后连读稿仍会误导下一轮复审

位置：原报告第 145—155 行的执行清单。

上一份完整复审已明确要求清理代表路线中的虚假标注。当前 `build-readable-script.js` 仍设置 `documentMarks`，连读稿第 801、1173、1595 行仍写“林旭阳标注……回拨后再问”。整合报告没有接入这项工作；仅运行检查也可能通过，因为生成器和错误阅读稿彼此一致。

建议增加：去掉生成稿中已取消的圈选及解锁承诺，重新生成并核对实际路线；旧字段先检查迁移和验证器依赖，再决定删除范围。不要直接删兼容配置。

依据：[上轮合并报告 G-05 与 A4](full-story-pacing-review-2026-09-17.md)、[阅读稿生成器](../../scripts/build-readable-script.js)、[当前连读稿](../generated/steam-demo-01-continuous-story-script.md)。

### 5. P2：保留基线错误地把转账材料来源也写成完整

位置：原报告第 26 行。

“序章酒店 → 转账两轮出示（来源、质疑、改口齐）”与第 73 行“序章三笔流水补来源”互相矛盾。酒店截图有平板同步来源，不代表银行转账材料也有来源。把两者一起列为无需改动的基线，会使执行者跳过已经确认的缺口。

建议改成：保留序章两轮满句对质和酒店材料的来源、质疑、回应；转账材料另补取得过程，并与不能查看账户的说法相容。

### 6. P2：把案一两夜共五个陈述阶段误写成第一夜五次

位置：原报告第 40、67 行。

`01-credit.json` 的第一夜场景为 `[0,1,2]`，第二夜为 `[3,6,7]`；五个普通陈述阶段对应 `[0]、[1]、[2]、[3]、[6]`，分布在两夜。不能用全案阶段数证明“第一夜五次微型陈述”。这不否定对话碎的问题，但会误导删并的范围。

建议准确描述“第一夜三个普通陈述阶段；两夜均有短段切换”，并用具体的陈述—回答—跳转指出断裂，不把阶段总数直接等同于节奏缺陷。

依据：[案一现行结构](../../content/packs/steam-demo-01/cases/01-credit.json)。

## 其余建议与证据边界

- U1 成立：[291.png](../../output/ui-walk/shots/291.png) 确实显示朋友圈选项拥挤，底部仍有“最该圈”的旧提示。它来自第一夜挂断后的匿名私信入口。报告写的 68px 不应当作已核实的最终计算高度；修复依据应是实际显示和点击区域。
- 人称统一、案一消费追问及挂断前定性、周会计提示理财、收入到设备的承接、材料索取、案二盈利追问等方向可以保留。
- 案三已经问过“其他账户为什么一直没回”，男方也已回答不公开且不接受付款条件。若使用表姐的新信息，应追“为什么发工资卡时不说明范围”，不要重复盘问其他账户有多少钱。此项应明确新增问题的对象和价值。
- “全剧信息峰值”“白天没出门”宜改为具体功能判断。没有离开工作室本身不是缺陷；NPC 是否带来发现才是问题。
- 第 147 行“授权范围”宜改为“建议修改范围”；本轮用户只要求复审，报告中的执行模板不能自行代表修改已获批准。
