## Part A|修复案3小尾声硬矛盾(逐字,立即)

**位置**:`content/packs/steam-demo-01/manifest.json` → `nightShell.interludes[2].lines[3].text`(案3广告间隙,林旭阳对赵律师)。

原文:
```
她家已经把九月底的钱算进婚礼了。希望到时候真能回来吧。
```

**为什么错**:案3反复钉死——女方家那二十万(宸直里的)是**「留给女儿自己,不是拿来付婚宴和首饰」**(案身说了 6+ 次;林旭阳自己的结案说「不把那二十万元算成可用资金」;同一 manifest 的表妹尾声也说「宸直那笔钱也不算进预算」)。这句"算进婚礼"把女儿对男方的**谎**当成了她家的事实,和案身、结案、尾声三重打架。

改为(逐字,去掉"算进婚礼"假陈述,保留对宸直兑付的担忧):
```
她家那二十万还压在宸直里，能不能按时兑，谁也说不准。
```

不动同 interlude 其它行、不动表妹尾声那句(它是对的)。

## Part B|四案系统性逻辑审计(报告优先)

对**纯文字剧本全文**(`docs/generated/steam-demo-01-pure-story-script.md`,必要时回 JSON 核)逐案跑三类检查,产出一份 `docs/review-archive/logic-audit-2026-08-10.md`(或按 DOCS-004 规则放合适位置)列出所有命中:

### 检查一·总结句 vs 案身事实(与 Part A 同型,最高优先)
逐一比对每案的**小尾声/广告间隙、尾声未读、结案卡、能确认/仍未知清单、材料卡**里的**概括性陈述**,是否与案身对话里已确立的事实一致。凡"总结/回味句把案身某事实说反或说漏"的,记下:案、位置、案身正确版本、离群句原文。**此类若正确值唯一,可直接修**(改离群句回到案身事实,同 Part A);有歧义则只报告。

### 检查二·数字/日期/时长闭合
把每案所有金额、日期、时长、比例列成账,核是否自洽且互不矛盾。重点:
- 案1:35,000 月薪、17,500×14=245,000、余额 11,600+、他以为 15万、房租 2×10,000、8万账单构成(4万共同+5千衣服+至少3.5万未明)、20万澄川/20万宸直/5万新阳/49,800→3301;交往"一年半"与"第五个月起十四个月"是否闭合。
- 案2:18 次/46,380、7 人推荐 4 人到店、六折/免单、十万→宸直。
- 案3:28.8万/28.6万/23.8万学费/18.8万表姐/30万宸直(20万留女儿)/8.4万她存(愿拿6万)/领证前进卡。
- 案4:6.8万垫款、14:05 群公告/14:22 私聊/九天后延后、返利与报销两条钱路。
任何一处不闭合(相加不对、日期矛盾、时长与转账月数打架)**只报告,不自行改数**(改数可能动到已锁账本)。

### 检查三·知识账本
逐拍核"说话人此刻能不能知道这条信息":有没有人引用了自己无从得知的麦外/夜B/对方私有信息(如案3男方上麦已由"我从头听到现在"补锚,核其余各处)。命中只报告。

### 报告格式
每条:`案N | 位置(场次/字段) | 类别(一/二/三) | 问题一句话 | 案身正确版本或存疑点 | 建议(已修/待定)`。检查一里已自动修的标"已修";其余标"待定,等你定"。
