# 2026-09-11 试玩修订与反复回退的原因

本次依据用户在 5194 试玩中的反馈，结束“只记录”阶段，直接处理序章至第一案白天材料段的问题，并检查为什么此前修改没有覆盖实际体验。

问题出在写作要求、运行时分支、校验和剧情档案之间的冲突。此前的审查主要盯住局部句子，没有把这些入口一起查完。这是修订流程的缺漏，不能靠换几个词解决。

## 找到的具体原因

1. **旧规范直接要求保留用户否定的写法。** `project-skills/case-scriptwriting/SKILL.md` 曾规定错选后只说“这条先放着”，隐藏选项自己的反馈；还要求普通回答与防备回答必须不同。这会把合理核实写成提前防御，甚至抢先谈起欠款和输赢。现已改为有动机才防备，合理事实问答可以直接回答；错选要说明当前选项的问题。
2. **测试把写作偏好当成了正确性。** `verify-pack.js` 曾锁定“能说明他平时挥霍吗”的反问；`verify-logic.js` 要求材料开场包含“先”“三月”，还逐字检查技能文件必须写“玩家至少完成两次实际回放处理”；`verify-narrative-flow.js` 要求每段至少两个选项。于是只有三万五一个关键问题，也会被迫凑问题。现已撤销这些冲突断言，仍检查来源、金额、提问锚点、有效回答和通关条件。
3. **改过的正文不一定是玩家听到的回答。** 同一问题有 `answer`、`guardedAnswer`、`lines`、`missReaction`、`reviewProbes` 等入口。共同花销问题原来被标成错问，会走旧反应；后续又默认固定转账已经问出。现已将这条设为有效提问，统一相关回答，把下一段必需的每月转账前提放在必经对白中，并更新结尾原话引用与相邻对白审查。
4. **运行时还会自行追加空泛文案。** 压力模型按语气或命中状态生成“话题岔开”“弹幕分成两拨”等旁白；材料入口把 `storyClueObject` 全案摘要当成材料标题。因此只改 JSON 台词也清不掉。现已停止无依据的自动旁白，保留具体编写的反应；材料入口只显示已收到的原件标题与原文。
5. **读档只刷新了台本，没有刷新已选回答。** `savedContentRefresh.js` 原先只替换 `caseBriefs`；`sceneQuestionPicks`、`sceneAnswers`、`evidenceCheckPicks` 和正在播放的探问仍保留旧文案，临时旁白也随存档恢复。因此旧进度确实可能再次显示删掉的句子。现已刷新这些播放快照，保存选项索引，清理过期临时旁白，并保留预算与已完成动作。历史案卷仍是当时记录，不会冒充新台词。
6. **当前剧情档案仍保留撤销的设定。** `story.md`、第六章、场景表、时间线、角色状态和悬念登记仍写着二选一、只回告所选路线、律师推荐机构等。现已同步为主播推荐、男方自行咨询、律师解释证据要求、两段顺序跟进。历史 review 留作历史，不再充当当前剧情依据。

内容索引构建器只是读取并导出内容，没有在游戏运行时重新生成台词。这里没有发现“模型更新后自动把新句子改回旧句子”的机制。

## 本次内容和交互修改

- 序章后半段按用户指定句子替换，纠正说话人，删除提前判断输赢、反复解释录不录像及未交代的接走孩子动作。妻子在散场半小时后发来语音。
- 机构信息由男方咨询后说出；主播推荐机构，律师解释后续证据与审查。亲子和家庭支出按顺序处理。旧存档只完成一段时补看另一段，再进入回告。
- 第一案共同花销、当月未转钱、八万缺口、五千男装、设备和礼物按反馈重写。账单唯一关键问题是三万五用途不明，留待明晚追问。一万二设备不再强制作为这一段的关键问题。
- 引入周会计并交代账页来自咨询者转交，移除突兀的“沈”、档案室和内部流水索引。错选显示“未选中关键线索”及具体理由；命中显示“已标注关键线索”。
- 材料窗口移到舞台外并调整层级，原文不再被舞台或示意图盖住。材料入口移至顶栏，标注气泡进入正常布局；名牌不再靠绝对定位贴边。
- 关键选项统一标注，跳过作为同级按钮；回放原话和选项分行占位，消除窄屏遮挡。回放开始有短过场。Esc 只关闭浮层，不再隐式回退追问。

亲子剧情保留必要法律条件：提供必要证据、对方没有相反证据又拒绝鉴定时，法院可以支持相应主张，不能写成“只要拒绝就自动判定”。依据为最高法《婚姻家庭编解释（一）》第三十九条：[官方原文](https://www.court.gov.cn/fabu/xiangqing/282071.html)。这段只在人物实际问到时回答。

## 验证结果与范围

- `npm run check` 全套通过；其中含 131 项逻辑检查、内容与生成文件一致性、八个日期样本的叙事流程、音频运行时和编辑器测试。存档刷新加入后再次运行全套检查，通过。
- 新增七项行为回归，覆盖旧存档回答刷新、单关键点通关、两条有效问题、错选反馈、Esc、材料来源与顺序后续；连同既有三组 UI/剧情回归共 25 项通过。
- Story 项目的链接、结构、连续性检查均为零错误、零警告；未揭晓的正式版悬念继续保留。
- 独立浏览器状态补验：亲子电话后进入家庭支出；共同花销实际回答为用户指定句子；材料命中与错选反馈；材料正文显示；Esc 保持当前追问；回放入场动画；390px 与 1366px 布局。390px 白天页实际测得材料按钮与继续按钮不重叠、无横向溢出。
- 补验使用独立状态，不覆盖用户试玩存档。本次没有重新通关四案的所有路径，也没有重做整套立绘资源。此前较早清单不自动全部结案。

后续改稿以实际播放路径为单位检查：谁先知道什么、问题承接哪句话、回答是否满足问题、下一段能否接上。禁止再用固定错问数量、固定防备句式和固定阅读教程代替这些检查。
