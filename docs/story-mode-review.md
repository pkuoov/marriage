# 故事模式剧情全面 Review

审阅范围：`src/caseEngine.js` 的固定故事案、`src/app.js` 的案件流程渲染、`src/screens.js` 的入口文案。  
说明：本文审阅的是现在已移动到“连环剧场”模式的双套进阶案件，不是新的婚姻主播主线。  
当前结构：教学章 1 案 + 第一套“资料包疑云”6 案 + 第二套“模板回声”6 案，共 13 案。

## 一、主要问题

### P0：第二套的核心问题不是“缺管理员 NPC”，而是责任判断模型不支持平台责任

第二套想问的问题是：“平台把真实痛苦做成产品，算不算伤害？” 这不是两名当事人之间谁更坏的问题，而是系统性提取、包装、分发和收费的问题。

当前指认系统只支持四类答案：
- 指向先诉苦者。
- 指向另一方。
- 双方都有隐瞒。
- 无预谋，只是关系失衡。

这套答案结构默认案件是两个人之间的责任分配。它能处理骗婚、半真半假、恶人先告状，也能处理告解里的自欺；但它不能处理第二套的主命题：第三方平台是否利用了关系痛苦。结果是玩家读完第二套主线会觉得“平台才是问题”，进入指认页却只能选林鹿还是陈默。这个落差会让第二套主题停在作者表达，而不是玩家判断。

需要的不是单纯新增 `platformAdmin`，而是新增一层责任维度：
- `premeditatedActorId` 支持 `platform` / `thirdParty` 这类非 NPC 责任源。
- `resolveAccusation()` 支持第三方指认。
- `expectedAccusation()` 能返回平台责任。
- `accusationLabel()` 支持“平台 / 第三方操盘 / 系统性提取”。
- `explanationForExpected()` 增加平台责任文案。
- `renderCaseAccusation()` 在故事第二套案件里显示“指向平台 / 第三方操盘”选项。
- `renderCaseSolved()` 拆成两层复盘：本案关系层、主线结构层。

新增 NPC 只能解决 UI 名字显示，不能解决玩法逻辑。如果平台责任系统不落地，第二套六案上线后会出现“读起来是平台案，玩起来还是情侣互撕”的根本错位。

### P1：固定主线和通用随机案模板混用，造成证词割裂

固定故事只覆盖开场、冷开场、悬念物、过场和部分主线证据卡；现场版本、普通证词、材料卡仍由通用案型模板生成。  
例子：第二套第一案主线是“平台入会测评”，但普通证词可能围绕“真实公司 / 名校背景”；第一套第五案主线是“被撤回语音 / 资料夹”，但普通证词仍会落到“暧昧称呼 / 没有身体接触”。

影响：玩家会感到“主线很精彩，但按钮点出来的证词不像同一个案子”。

建议：
- 每个固定案增加 `storySceneVersions`、`storyTestimony`、`storyEvidenceCards` 覆盖通用生成。
- 保留通用模板只作为兜底，不作为固定剧情主证词。
- 每案至少 3 条专属追问：时间线、利益路径、叙事动机。

### P1：教学章没有真正变成教学流程

教学章现在只是多了教学提示，但玩家仍然可以直接跳到证据、使用启发道具、进入指认；它没有强制玩家体验“比对现场 -> 追问证词 -> 选证据 -> 出示证据 -> 指认”的完整闭环。

影响：新玩家可能仍然不知道关键操作在哪里，教学章的存在感主要是文案。

建议：
- 教学章限制流程：必须至少完成 1 次现场比对、1 次证词追问、1 次证据出示，才开放阶段指认。
- 教学章的启发道具改为“孟姐提示”，第一次免费且不扣次数。
- 教学章结案复盘明确列出：你在哪里找到矛盾、它如何变成证据。

### P1：13 案体量和重复流程会放大疲劳

故事模式现在是 13 案。按每案 8-12 分钟估算，一次完整通关约 1.5-2.5 小时。这个体量对核心玩家可以接受，但对普通玩家有明显风险。

更大的问题不是时长本身，而是第二套前三案的流程仍然和第一套高度相似：当事人带材料来 -> 复盘现场 -> 追问证词 -> 整理证据 -> 指认。第二套只是主线文本换成平台测评、征信报告、延期保障，但玩家的操作结构没有变化。如果通用证词继续存在，第 8-10 案会明显出现“我之前做过这个”的疲劳。

建议：
- 第二套至少 2-3 案改变调查结构。
- 第二套第一案可改为“核验平台测评是否复用了第一套资料”，重点查模板来源，不是查沈知夏 / 许照谁错。
- 第二套第二案可改为“验证风险报告是否伪造或非法裁剪”，重点查数据来源。
- 第二套第五案可让“平台顾问”第一次主动联系玩家，制造对手感。
- 第二套终局不应只是又一次告解，而应是对前面平台证据链的审判式复盘。

### P2：第一套到第二套的桥接过早明牌

`storyBridgeClue` 在开案页直接显示“跨套关联”，第二套第一案一开始就告诉玩家“平台才是把叙事模板商品化的人”。  
影响：悬念从“玩家推理出来”变成“系统提前宣布”，削弱第二套前半段的调查快感。

建议：
- 开案页只显示模糊提示，例如“这份材料的格式似曾相识”。
- 真正的 `bridgeClue` 放到证据页或案间过场，在玩家至少抓到 1 个矛盾后显示。
- 第二套前三案逐步揭示：测评表格式 -> 报告水印 -> 婚庆合同推荐人 -> 平台后台。

### P1：线索链目前是文本连接，不是玩法连接

现在的线索链主要依赖 `storyTransition` 和开案冷场文本：玩家读到“合同编号弹出旧记录”，然后自动进入下一案。这个连接成立于叙事层，但没有形成玩家亲手发现的破案记忆。

侦探故事里更有力量的体验应该是：玩家在第二案证据卡里见过“婚庆经理编号”，第三案追问时亲手翻出同一个名字。也就是说，上一案证据应该进入玩家调查档案，下一案追问或证据卡应按 ID 引用旧证据。

建议建立跨案证据系统：
- 结案时把关键主线物证写入 `state.caseArchive` 或新的 `state.storyEvidenceArchive`。
- 每张主线证据卡有稳定 ID，例如 `story-02-contract-code`。
- 下一案的 `storyTestimony.followups` 可声明 `requiresEvidenceId` 或 `referencesEvidenceId`。
- 玩家点追问时，如果档案里有对应证据，显示“你调出上一案的购房合同编号”；没有则只显示模糊提示。
- 结案复盘列出“跨案证据命中”，而不是只列本案矛盾数。

没有跨案证据追踪，两套案件会像共享风格的独立案；有跨案证据追踪，玩家才会觉得自己真的在破一条连环案。

### P1：第二套前三案缺少“平台如何知道这些信息”的证据层

第二套最重要的悬念不是“平台很可疑”，而是平台如何拿到第一套当事人的信息，并把它转成测评、报告和服务。

当前缺口：
- 测评表为什么能复用第一套“稳定推进 / 安全感 / 婚礼压力”？
- 风险等级报告的数据从哪里来？
- 征信截图、资产截图、婚礼合同和家庭互助小程序之间如何共享数据？
- 陪伴顾问怎么知道第一套被撤回语音里的原句？

如果这些问题只靠开案文本暗示，第二套会停在“氛围上很像阴谋”；如果玩家能在证据卡和追问里抓到数据链，第二套才有破案成就感。

建议给第二套前三案补一条证据链：
- 第二套第一案：测评表 HTML / 表单导出里出现第一套资料夹字段名。
- 第二套第二案：风险报告元数据里出现测评表用户 ID 和上传时间。
- 第二套第三案：延期保障合同推荐码与风险报告水印一致。
- 第二套第四案：亲属互助小程序读取过风险报告等级。
- 第二套第五案：陪伴顾问后台能看到互助小程序的“高情绪依赖”标签。
- 第二套第六案：告解模板后台统一展示这些数据流。

### P2：部分案子的本案责任和主线责任冲突

多案文本把“平台/婚庆经理/系统”作为真正操盘者，但玩法层仍要求玩家在两名当事人之间指认。  
典型案：
- 第二套第三案：剧情矛盾是延期保障合同和婚庆经办人，但 `premeditatedActorId` 是何念。
- 第二套第四案：剧情矛盾是亲属互助小程序，但 `premeditatedActorId` 是陈默。
- 第二套第五案：剧情矛盾是陪伴服务，但没有平台责任选项。

建议：
- 新增 accuse 选项：`platform` / `thirdParty`。
- 普通案仍可判断当事人责任，故事案可额外判断“第三方操盘”。
- 结案复盘拆成两层：本案关系责任、主线组织责任。

### P2：告解时间线机制出现太晚

告解时间线是独立于现场复原、证词追问、证据出示的一套玩法。它第一次正式出现就在第一套第六案，而第六案正好是情绪密度最高、主线信息量最大的终局。

风险：玩家在终局第一次学习新机制，会把认知负担和剧情负担叠在一起。终局应该考验玩家前面学过的东西，而不是临时教新规则。

建议：
- 教学章加入 1 个迷你告解节点，例如“这句话是被坑、自欺，还是也可能伤人？”
- 第一套第三案可插入 1-2 节点短告解，因为它当前是 personalityMismatch，相对适合承接轻量机制教学。
- 到第一套第六案时，告解时间线应被玩家视为熟悉机制的高压版本，而不是第一次接触。

### P2：第一套第三案存在线索表述错误

第三案 suspense 写“酒席名单里出现了第一案房产合同旁同一家婚庆公司的经办人”。第一案没有房产合同，房产合同属于第二案。  
建议改成：“酒席名单里出现了第二案购房合同附件旁同一家婚庆公司的经办人。”

### P2：若干悬念点出现后没有回收

未回收或弱回收点：
- 第二案“镜头外，有人轻轻敲了两下桌面”没有后续解释。
- 教学章“孟姐的红线笔记”中段缺少持续出现，只在第二套终局回收。
- 第一套终局“资料夹最后一页没有证据，只有孟姐批注”语气过于收束，接第二套时张力略断。

建议：每 2-3 案回收一次红线笔记；“敲桌声”可设为顾问管理员或婚庆经理的线下提示。

## 二、玩家实际流程

故事模式入口：
1. 标题页说明故事模式有教学章和双主线。
2. 创建页选择故事模式和侦探专长。
3. 生成 13 个固定故事案。
4. 每案流程：开案 -> 现场复原 / 告解时间线 -> 证词追问 -> 证据卡 -> 阶段指认 -> 本案复盘 -> 案间战况。
5. 本轮复盘后进入关系后续。

线索实际出现位置：
- 开案页：冷开场、案由、主线疑问、悬念物、跨套关联、本周目线索。
- 现场复原：场景描述、双方版本、现场矛盾。
- 证词页：证据卡可选、证词追问、出示证据。
- 证据页：主线物证详情、跨套线索详情、材料卡。
- 结案复盘：已抓矛盾、错过关键点、后台真相。
- 案间战况：`storyTransition`，负责把本案线索推向下一案。
- 告解案：告解时间线节点，玩家标注“被坑 / 自欺 / 可能伤了别人”。

## 三、教学章

### 教学章：第一处矛盾

主线流程：
- 开场：孟姐用旧案教学，指出转账时间、被删动态、“先别问细节”。
- 悬念物：孟姐的红线笔记。
- 过场：红线笔记指向第一套匿名资料包里的“稳定推进”。
- 核心教学：不要先站队，先找时间线、钱和台词矛盾。

线索在哪里：
- 开案页：旧录屏、红线笔记、三处发亮点。
- 现场复原：同居出租屋，双方版本。
- 证词页：追问“表态”“具体日期”等通用矛盾。
- 证据页：红线笔记、直播录屏、微信截图。
- 案间战况：红线笔记转入匿名资料包。

问题点：
- “孟姐教学”没有强流程控制，玩家可以绕过关键教学动作。
- 教学章用林鹿 / 周砚当旧案当事人，后续他们又进入正式案，可能造成身份混淆。
- 红线笔记在第一套中段缺少显性回收。

## 四、第一套：资料包疑云

第一套主题：真实关系如何被包装成叙事。它从“资料包装”开始，经过房本、婚礼、亲属债务、情绪外包，最后进入许照的告解。

| 案件 | 关键对话 / 开场 | 关键线索 | 线索位置 | 有问题的点 |
| --- | --- | --- | --- | --- |
| 第一案：完美资料 | 何念说只是被误会包装；匿名资料包显示她提前准备另一套叙事。 | 被删动态截图、“稳定推进”、匿名资料包。 | 开案冷开场；证据页主线物证；案间过场放大房产中介 LOGO。 | 普通证词仍是通用“学历 / 育儿责任”等模板，和“匿名资料包”主线不够贴。 |
| 第二案：房本安全感 | 周砚回应第一案：“安全感为什么不能写进合同？” | 购房合同角落手写编号。 | 开案页；证据页主线物证；案间过场出现婚庆经理旧记录。 | “镜头外敲桌”未回收；普通证词不够体现父母出资、贷款资格、退出机制。 |
| 第三案：酒席和彩礼 | 婚庆经理先传尾款单，备注“退婚原因不要写真实的”。 | 婚庆尾款单、婚庆经理经办记录。 | 开案冷开场；证据页主线物证和额外排期表；案间过场露出亲属借款。 | 文本误写“第一案房产合同”；本案设为 personalityMismatch，但主线显然有第三方操盘。 |
| 第四案：亲属债务 | 林鹿问亲属借款为什么经过婚庆尾款进入共同账户。 | 家庭群截图、共同账户、担保/借条日期。 | 开案页；证据页主线物证；案间过场出现“项目咨询”转账。 | 陈默被设为预谋方，但如果家庭系统是主因，需要区分陈默主动恶意和被家庭裹挟。 |
| 第五案：同事情绪外包 | 沈知夏展示聊天记录；许照删掉的不是暧昧，而是“资料夹”。 | 被撤回的深夜语音、音频恢复。 | 开案页；证据页主线物证和音频恢复；案间过场打开终局告解。 | 很强的一案，但普通证词仍偏“暧昧称呼 / 身体接触”，没有足够围绕资料夹追问。 |
| 第六案：告解终局 | 许照打开六案共用资料夹，说前五案其实也在查他。 | 六案共用资料夹、六个告解节点。 | 开案页；证据页资料夹；告解时间线；结案复盘。 | 第一套结尾过于像全剧终章，第二套开场需要更强“资料夹没有封存”的钩子。 |

第一套整体评价：
- 优点：悬念物递进清楚，过场链条基本成立：被删动态 -> 房产合同 -> 婚庆经理 -> 亲属债务 -> 深夜语音 -> 共用资料夹。
- 弱点：中间案件的通用证词削弱了“资料包疑云”的专属感。
- 建议：第一套每案增加一个“资料包标签”证据，如“稳定推进”“安全感”“都到这一步了”“先帮家里”“你懂我”“我只是复盘”。

## 五、第二套：模板回声

第二套主题：第一套的真实痛苦如何被平台化、模板化、收费化。它应该不是“换一批案子”，而是第一套的证据被系统拿去做产品。

| 案件 | 关键对话 / 开场 | 关键线索 | 线索位置 | 有问题的点 |
| --- | --- | --- | --- | --- |
| 第二套第一案：入会测评 | 沈知夏带来平台入会测评表，里面复用了第一套话术。 | 平台入会测评表、第一题“你愿意为安全感支付多少成本”。 | 开案冷开场；证据页主线物证；跨套线索。 | 过早明牌“平台才是商品化的人”；玩法仍指向沈知夏 / 许照，不指向平台。 |
| 第二套第二案：征信镜像 | 周砚收到匿名征信截图，标题《婚前风险等级》。 | 婚前风险等级报告、宴席延期保障水印。 | 开案页；证据页主线物证；案间过场指向延期保障。 | “匿名截图来源”缺少可追问对象；普通证词偏网贷/失业模板。 |
| 第二套第三案：延期保障 | 何念上传婚礼延期保障合同，推荐人是第一套婚庆经办人。 | 婚礼延期保障合同、家庭沟通模板。 | 开案页；证据页主线物证；案间过场指向亲属周转。 | 何念被设为预谋方，但真正操盘者是合同/经办人/平台，责任层级需要拆。 |

- 优点：主题比第一套更清楚，且有时代感：测评、征信报告、延期服务、家庭小程序、陪伴顾问、告解模板。

### 文本链和玩法链的差距

当前体验：
- 玩家读到“婚庆经理旧记录”，下一案自然出现婚庆经理。
- 玩家读到“风险报告水印”，下一案自然出现延期保障合同。
- 玩家读到“高情绪依赖用户”，下一案自然出现陪伴服务。

目标体验：
- 玩家在前案获得证据 ID。
- 下一案某次追问会引用这个证据 ID。
- 玩家亲手触发“旧证据命中”，获得跨案矛盾。
- 结案复盘显示跨案证据命中率。

这一步比单纯补文案更重要，因为它决定主线是否是“玩家破出来的”。

## 八、整体判断

第一套的剧情完成度较高，悬念链基本成立。它最需要的是专属证词、专属现场版本和少量文本修正。优先推进第一套的固定案专属化是合理的。

第二套的主题潜力比第一套更强，但它目前仍处于“文本层设计完成，玩法层空缺”的状态。它不是简单的六个新案，而是要求系统支持第三方责任、跨案证据、平台数据链和不同调查结构。平台责任系统落地前，不建议继续大量扩写第二套对白，否则会放大“读起来像平台案，玩起来像情侣案”的落差。

更稳的推进顺序是：先用第二套第一案或第二案做平台责任玩法原型，确认玩家能指认“平台操盘”并在复盘中看到结构层责任；再重写第二套后续案件。第一套则可以并行做专属证词改造，因为它不依赖新责任模型。
