# 《直播间大侦探》章节式案件包设计总纲

## 核心定位

《直播间大侦探》不是低成本互动影游，也不是性别对立短剧。它是一档可以玩的直播间推理节目：现实、克制、戏剧性强，每一案都像评论区会爆，每一次选择都暴露玩家自己的判断习惯。

一句话定位：

```text
现实评论区版逆转裁判。
```

不是法庭，不是刑案，不是浮夸大反转。玩家作为主播，在一通来电里把一句“听起来没毛病”的话，慢慢问成“原来这里藏了利益、面子、责任和成本”。

## 产品形态

主模式按 Steam 试玩版“章节式案件包”落地：

- 首发试玩当前采用一集四案，但这只是 demo 包规模，不是引擎铁律。
- 后续每次发版都是一个案件包，类似《逆转裁判》的章节包；可以是三案、四案、五案，甚至序章+大案。
- 同一包内案件必须是一个有机整体，不是随机拼盘，也不是按自然周刷新的短案。
- 总游戏时长按包规模控制，当前 demo 目标约八十到一百分钟。
- 每案仍然是一通匿名连线。
- 每案至少 5 个关键来电段，目标支撑 20 分钟以上的选择、回看和复盘。
- `daily` 是单案内容单元和兼容入口，不再是主产品叙事。
- 正式版按故事集内容包发布，老集进入 archive，新玩家可以补课。

试玩集结构：

```text
第一案 / 体面：恋爱消费和债务，先让玩家听见“心疼”和“买单”的缝。
第二案 / 自己人：暧昧话术和店内转化，把亲密感推进到消费、带客和投店。
第三案 / 条件：资料包装和收入诉求，反问来电人自己的修剪。
第四案 / 主责：职场报销和流程入口，离开婚恋场景，证明玩法能处理公共生活事件。
```

## 案件包结构

案件包不能按“同题材连发”来做。每包必须有一条整体推进。四案包可以用四幕结构；非四案包也要有等价的起伏和回收：

```text
起：建立主题和玩法，让玩家先相信一个好听词。
承：把同一问题放大到更高成本、更长时间或更多人参与。
转：反过来审视来电人，打破舒服的单方审判。
合：换到另一类公共生活场景，证明本集判断方法可迁移。
```

试玩集对应为：

```text
体面 -> 自己人 -> 条件 -> 主责
短债 -> 亲密转化 -> 来电人自利叙事 -> 公共流程入口
```

每案结束时要留下一个“下一案问题”，不是简单播下一条：

- 第一案后问：如果不是直接借钱，而是用亲密感慢慢把人推向消费呢？
- 第二案后问：如果不是对方包装你，而是你和家里也在包装对方呢？
- 第三案后问：如果离开婚恋，身份词还会不会转嫁成本？
- 第四案后问：四个场景里，谁把好听词变成了付款入口？

故事集要有主播弧线。玩家不是做四道判断题，而是在四案里逐渐形成自己的听话方法：

- 从接情绪，到问账单。
- 从听亲密，到看表格。
- 从查对方，到反问来电人。
- 从看截图，到追流程入口。

这一条弧线决定尾声不能写成说教总结。尾声只展示玩家一路追问形成的倾向，以及四案中已经听过的原话如何互相照亮。

每个故事集必须有一个主题，例如：

- 钱不是钱，是成本往哪落。
- 截图是真的，意思可能是剪过的。
- 半句真话，最容易互相伤人。
- 身份标签，不该替责任背书。
- 好人为什么会被坏行为拖进局里。

## 价值观

价值观要正，但剧情不能被净化。

本作不靠性别对立收割流量，不把“男的都怎样 / 女的都怎样”当爽点。游戏要团结愿意真诚沟通、愿意承担责任、愿意保护边界的好人；真正要打击的是撒谎、操控、利用善意、转嫁成本、借身份或关系压人的坏行为。

同时，现实里很多事确实是双方互害。双方都可能说半句真话，隐瞒对自己不利的事实，拿关系、面子、家人、钱或机会试探对方。这样的案子不但可以写，而且应该写得更清楚。

互害案不能用一句“两边都有问题”收场，必须拆成：

```text
A 做了什么伤害 B？
B 又做了什么伤害 A？
哪一方先启动失衡？
哪一方借善意、身份、家庭、平台或制度扩大了伤害？
谁承担了实际成本？
谁把自己的利益包装成道德要求？
下一步边界是什么？
```

## 和同类作品的差异

参考方向：

- 《逆转裁判》：爽点来自自然追问后抓住矛盾，不是来自选项数量。
- 《Her Story》：玩家主动拼接碎片，真相不是系统喂给玩家。
- 《IMMORTALITY》：素材浏览本身成为推理路径。
- 《Not For Broadcast》：直播间身份让玩家决定什么被放大、什么被解释。
- 国产互动影游：轻操作、强代入、可传播，但容易滑向表层分支和情绪收割。

本作不要卷真人素材或分支树数量，而要卷“推理解释权”：

```text
玩家不是在选剧情，而是在决定这一句该怎么理解、该往哪条线追。
```

## 单案结构

每案必须是一个小压力系统：

- `whyTonight`：为什么今晚打来。
- `dramaticAnchor`：截图、流水、排班表、合同、账单、录音、聊天原话等戏剧物件。
- `objectPurpose`：这个物件想证明、遮住、拖延、说服或推动什么。
- `callerStake`：来电人讲成这样能保住什么，淡化了什么。
- `otherStake`：对方展示/隐藏/改口能得到什么。
- `thirdPressure`：父母、老板、平台、朋友、前任、中介、舆论等是否参与推动。
- `truthBoundary`：哪些是真的，哪些被修剪，哪些仍不可证。
- `audienceArgument`：评论区最后会吵什么。

材料中心案必须先写清楚四层：

```text
true：材料本身能证明什么。
edited：缺了哪一边、哪一页、哪段上下文。
possiblyFalse：材料暗示的结论可能哪里不成立。
unknown：本次连线仍无法证明什么。
```

## 玩法循环

前台保持线性：

```text
咨询者讲一段
-> 玩家选择主播这一句怎么接
-> 咨询者回答
-> 下一段来电
-> 查看一份材料，指出截图、账单、表格或审批图里最该圈出的缺口
-> 满格路线进入一个非选择深问
-> 选一句原话回应
-> 单案复盘
-> 下一案 / 故事集总结
```

硬规则：

- 每个关键节点只能问一个选项。
- 问完直接进入下一段，不能扫同节点剩余选项。
- 每案至少有一个材料检视节点。它不是教程提示，而是让玩家亲手指出“哪一栏不对、哪一页缺了、哪句原话和哪张图冲突”。
- 关键追问命中和材料检视选对不消耗听众忍耐；外围绕问、重复问或材料误指才消耗。
- 每次屏幕对话最多两个来回；文本多时压成一问一答。
- 回看只允许看上一次关键选择之后；第一次选择前只能回到开头。
- 满格才出现一个无选择的深入一问。
- 最终选的是已经出现过的原话，不是抽象结论。

## 后台路线图

每个选项都要记录路线轴和语气倾向。

路线轴包括：

- 来电人可信度线。
- 对方叙事线。
- 钱流结构线。
- 材料缺口线。
- 身份话术线。
- 流程入口线。
- 核心矛盾线。
- 外围试探线。

路线图不是新菜单，不打断主流程。它只在复盘里显形，让玩家意识到：

```text
我不是“答对/答错”，我是一路用某种判断习惯在听这通电话。
```

故事集总结要根据四案路线生成主播倾向，例如：

- 钱流雷达主播。
- 截图拆边主播。
- 反向追问型主播。
- 入口控制型主播。
- 现场嗅觉型主播。

## 评论区审判墙

故事集总结要出现评论区审判墙。它不是系统教学，而是把玩家路线变成可传播的评论区语感：

```text
“这主播这一集明显偏钱流结构线，不是爱站队，是先看哪句话能落到责任上。”
“截图那案问得最稳，材料缺口一出来，前面的体面话就不能按原样听了。”
“好看的点是它没有硬判好坏，谁修剪事实、谁转嫁成本，都得一条条摊开。”
```

评论墙要遵守：

- 不攻击性别或群体。
- 不替玩家道德说教。
- 不提前泄露未完成案件。
- 评论必须来自玩家实际路线、揭示率和本集主题。

## 内容选题

题材不限婚恋，优先现实公共生活事件：

- 婚恋：学历包装、收入流水、婚前房、彩礼边界、共同还贷、工资管理。
- 职场：报销截图、署名、供应商返款、老板借口、同事垫款。
- 消费：退款、预付卡、服务承诺、截图证明。
- 租房：押金、维修、合租责任、房东中介话术。
- 平台交易：规则、客服截图、代运营、履约口径。
- 熟人借贷：借赠边界、转账备注、共同消费。

每案都要有：

- 一个评论区能立刻有画面的标题。
- 一个现实锚点。
- 一个戏剧物件。
- 至少三处逐步揭示的问题点。
- 一个可以互相争论但不能靠性别标签偷懒的结论。

## Steam 发版管线

不要承诺每天或每周远程更新。Steam 主节奏应是“一个发版内容包 = 一个章节式案件包”：

```text
至少提前储备 2-3 个案件包。
首发试玩先做当前四案 demo；正式版每次发包按主题和节奏决定案数，不固定四案结构。
内容包数据化：content/packs/<pack-id>/manifest.json + cases/*.json。
发布前跑自动校验 + 浏览器回放 + 人工串读。
旧集进入 archive。
Steam 公告/活动页发布本次故事集主题。
```

内容生产节奏：

```text
阶段一：确定本集主题和四案候选。
阶段二：写四份压力系统。
阶段三：写 stitched transcript。
阶段四：拆字段、录入内容包、跑校验。
阶段五：浏览器实测、文案修订、构建。
阶段六：进入 archive，并准备下一包故事集。
```

## 质量红线

禁止：

- 性别对立、群体攻击、标签化收割。
- 单方纯受害叙事，除非是明确纯骗局。
- 为了正能量抹掉双方互害。
- 用“两边都有问题”代替具体责任分析。
- 主播提前知道答案。
- 材料凭空出现。
- 反馈直接讲大道理。
- 选项里出现明显没人会点的废选项。
- 把法条、咨询、教学当玩法。

必须：

- 先写压力系统，再拆 UI 字段。
- 每个材料都有出现目的。
- 每个问题只基于已经出现的信息。
- 每个结论都能在前文找到事实支撑。
- 每次改动都重读完整链条。
- 自动校验后，还要实际玩一遍。
