# 本地台词审阅工具

在项目目录运行 `npm run edit:dialogue`，打开 <http://127.0.0.1:5186>。仅在本机提供服务，按 Ctrl+C 停止；端口被占用时使用 `npm run edit:dialogue -- --port=5187`。不需要 API Key。

## 改一段对白

1. 按案件、角色、阶段或关键词筛选，选择一句；用“上一句／下一句”连续浏览筛选结果。
2. 连着上下文阅读，在编辑框里修改，查看原句与改句的差异。
3. 有值得保留的判断时，填写原因、适用范围和例外。可以留空，稍后补充；没有具体原因的记录先不推广。
4. 点击“保存台词修改”（⌘ / Ctrl + Enter）写回工程；拿不准时选择“只记问题，保留原句”，保存候选改法而不修改源台词。
5. 查看右侧检查结果。保存会同步内容索引、阅读稿与审查报告，并运行 `npm run check`；检查期间可以继续起草，完成后再保存下一句。

输入会留作当前浏览器的本地草稿，刷新或换句后可以找回。清除浏览器数据会删除草稿；草稿不等于已保存的工程修改。

发现有意重复、人物歪理、官腔或跑题时，也可以保持原句、填写原因，再点“保留原句，记录原因”。这会记录当前上下文中的保留判断，不改变台词、不触发报告重建，也不会让该句今后免检。源文件变化后仍需重新核对。

“改与保留的对照”按所选问题类型显示相关示范，包括喜剧被解释、有意重复和误会反转。六组起始示范在 `content/editor/dialogue-calibration.json`，均未获用户逐条认可，不能作为正式剧情或自动替换模板。实际使用后，再从真实修改与保留记录中补充例子。

原来会阻断生成的四种句式已改为审读提示：人物可以故意说“本质上”或“一方面／另一方面”。自动工具不判定一段话是不是好笑或应不应该重复，人物归属、源位置与事实锚点检查仍独立执行。

## 上下文的范围

第一版复用角色台词报告的提取逻辑，覆盖该报告已收录的主案、快案、序章、幕间、尾声与人物材料；当前为 1,358 个可编辑位置。没有收录的界面文案和未映射位置不开放编辑。

上下文按源文件顺序展示同段或同选项附近的文本，不跨兄弟选项拼接。它可能包含普通回答与防备回答、兼容字段等多个版本，并不重建实际玩家路线。防备回答单独标记；鼠标停留可查看字段路径。判断信息是否提前泄露时，仍需结合实际路线复核。

右侧人物卡和现有审查约束是作者参考，可能包含后续信息。“同文位置”只检索完全相同的文字，逐处查看，不自动批量替换。

## 保存与撤回

每次保存只替换选中 JSON 字符串，保留其他字段、缩进与排列。源文件版本不一致时拒绝覆盖；刷新、比较并选择“以当前原句继续修改”后才能基于新版保存。

修改和问题记录保存在 `content/editor/revisions/<记录 ID>.json`，包含原句、候选句、角色与约束快照、上下文、理由、范围、例外、版本摘要和写入状态。应随内容修改一同保留在版本管理中。记录用于积累真实编辑案例，不会自动变成技能规则。

在“修改记录”中可撤回源文件尚未再次变化的修改；撤回会生成一条新记录并重新检查。若后来改过同一文件，先撤回后续改动，或对照记录手动编辑，不能强行覆盖。文件中的数组重新排序后，旧位置也需要重新核对。

保存中断时，记录会显示已写入、未写入或需核对，不会自动重放。检查失败不会撤销已经保存的台词；可以继续修正或从记录撤回。服务重启后检查状态清空，持久记录仍保留。

## 检查不能替代审读

工具不会自动改写 `sourceAnchor` 等审查锚点，也不会把已有语义审核标成通过。每次改句的记录都保持“语义待复核”；工程检查通过只说明现有自动检查通过，不保证人物动机、接话和事实边界都成立。

开发回归：`npm run test:dialogue-editor`。测试使用临时内容副本，包含本机 HTTP 服务测试，不修改正式台词。
