# 二次改稿：现场对白与逐层揭露

适用于现有台本的二次审读。跨技能约定仍以[当前项目方向](current-project-direction.md)为准。本文件解释如何识别摘要式对白，不另设句长、问数或场次配额。

## 先听这一段在说什么

按玩家首次遇见的顺序读完整交换，分别核对：玩家已经知道什么、目前可能怎样理解、作者另知道什么、本场该揭开什么。材料、选项和旁白都属于玩家所见，不能只把剧透从对白挪到卡片或标题里。

台词首先像这个人此时对另一个人说话。短句可以是即时反应，长句可以是争辩；不要以更短、更整齐、更像论证为优化目标。被省掉的主语、对象、指代或因果让人需要补读时，把话补全。已经充分发生的事实，不再补流程小结、心理归因或主题。

“先、所以、你刚说、交代、说到底”只是复查入口，不是禁词。不要靠加“啊、吧、就是”修复摘要式句子，也不要反过来每次都添“等一下”。

## 主播的反应

抓当前最需要问的行为，不把三件已知事实重新打包成一道论证题。刚看过的材料无需完整复述；金额本身用于当面核对、对方没看见材料或读出数字会触发反应时，可以念。

少用“你最想让我替你说什么”采集诉求。围绕正在争的钱、约定或行为发问，让来电人自己表态。怀疑有依据可以问，讽刺也可以有；不把“你心里就是……”写成主播替玩家解说的确定心理。

反应、打断、追问可以发生在一句或几句里，不固定“反应—矛盾—问题”三拍，也不要求每轮两连问。收尾看人物现在做了什么、还要做什么；试删最后一句，如果前后接话仍成立、没有丢行动结果，就不补回同义判词。

## 来电人与第三人

来电人维护自己的立场，不主动把不利事实整理成罪状。他们可以只回答半个问题、抓住刺耳的词争辩、回避或改口；不要把这些都修成问什么答什么。多个新事实挤在一段时，按真正的争议拆开，由问题、反驳或材料带出，不按数字门槛强制拆轮。

第三人先是有处境的人：对方在向谁抱怨、反驳、求助或追讨？信息从这段交流里出来。不是每位 NPC 都必须先抱怨，也不为“有目标”新增恩怨。只需一个自然的联系来源，不能用旁白把其心理目的说明白。可合并没有独立作用的人物；保留时应有真实分歧或关系，不能靠多说几句资料伪装丰满。

## 职业、数字与动作

柜员说业务规则、鉴定人读技术意见可以正式；律师的日常安慰不必面面俱到。会计可以发现数字异常、让人翻页、口头算账，不必每次给出完整分析报告。原件保持精确，人物是否报全数字取决于此刻是否要核对。

动作保留可感知的作用：带来信息、改变情绪或场景、发生事件、回应操作。单纯为了隔开对白而加的翻纸、吸气、手机磕桌可删。听筒里没有交代声音来源时，不代看电话另一头的动作。

四案可以共用玩法，冲突节奏不必相同。来信、拒答、延迟补件或争执按各案已有处境展开，不为了“至少一案拿不齐”硬造阻碍。

## 接入后怎样核对

先查看实际播放字段，尤其 `lines`、`acts[].inquiry`、`afterVersion` 和场前反应；把首述里的事实移入回答时，同时检查回答前是否已有一句引用它。旧原话引用、材料摘录、邻接锚点和人物卡一起同步。材料不能从旧的未播放证词墙取一段原话冒充角色刚说过。

通读与出声朗读分开记录，没有实际出声就不要报告“朗读通过”。检查修改后的完整交换、场尾删句和不同角色的表达；无需每场固定六遍。稳定 ID 和可达路径照常验证，不用整句正则锁住此次措辞。
