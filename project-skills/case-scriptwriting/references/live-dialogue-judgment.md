# 直播对白：判断改哪里，也判断保留什么

适用：起草或审读连线、主播反应、闲聊、喜剧和反串。遵循[当前项目方向](current-project-direction.md)，这里保留判断“该改与该留”的方法，不另规定每案结构。

## 三件事分开看

作者知道实际发生的事。玩家能取得哪些事实由路线与材料决定。这两层要能对得上。

人物的话可以错误、跳跃、重复和自相矛盾。他可能忘了刚才的说法，也可能认为自己的例外天经地义。写得好时，观众能跟上他的想法，还能发现这套想法有多偏。

主播有自己的脾气，可以笑、误会、接梗、短暂附和或追一句很生活的问题。边界主要体现在他最后做了什么、系统确认了什么；不要让他每遇一段歪理就讲证据课。平常连线可以只留下一个反应或一句没接下去的话。

## 荒诞也可以是主要冲突

“啊，还有这种神人”往往来自一个人很认真地维护奇怪的标准。起草时，在作者笔记里想清楚：他觉得哪件事天经地义；希望别人因此替他做什么；碰到反例时会怎样给自己留例外。答案不用交给角色自我剖析，也不需要每个人都在算钱或故意害人。爱面子、怕麻烦、要仪式感、过分较真或单纯想被夸，都能撑起一段。

好笑可以出在要求本身、奇怪的执行细节、主播先误会了身份、当事人无意补出更离谱的一层。不要固定成“听起来正常 → 连续三次升级 → 主播一句金句收尾”。普通闲聊、真诚的笨拙和温和收场同样需要。

重复时看人有没有在加重态度、争词、回避、修补说法或等对方认同。跑题时看观众能否跟上注意力怎么变了。没有提供新证据不等于没有戏；喘口气、显出日常习惯和让人觉得好笑，本身就有作用。

反串或反转可以误导主播与观众的理解，但作者不能临时改账。人物若在演，预先想清楚为什么来演、想影响谁、哪里留过痕迹；别用结尾一句“全是演的”抹掉已经发生的事。角色可以说未经证实的话，叙述、材料与系统结算不自动替他认证。

## 减少同类问题复发的做法

每次改稿前，读取与问题有关的少量对照例，而不是把整份大 skill 当成禁句清单。[对照库](../../../content/editor/dialogue-calibration.json) 包含六组起始示范，标记为 `illustrative-not-user-approved`，不是用户已接受的正式台词。

实际编辑判断留在 `content/editor/revisions/`：原句、改句、前后文、具体原因、适用范围、例外。遇到有意重复、歪理或官腔时，用编辑器的“保留原句，记录原因”保存正例。保留只对这份源版本和上下文成立，不是今后不可修改的免检标记。

一次编辑经验先在相邻或同类场景试用；只有再次成立时才考虑扩大适用范围。推广前同时检查“应修改”的例子和“应保留”的例子；如果候选规则会删掉后者，就缩小规则，不能把全部角色修成一样的人。

后续模型或提示词变化时，重新给这些小段提出改法，再比：是否修掉作者的机械接话；是否保留人物的歪理、重复与喜剧；有没有新增事实或抹掉人物目的。记录具体改法与未通过之处，不用一句“模型自评通过”取代比较。

当前自动检查能保住路径、原话锚点、数值和保存冲突。句式命中只提示审读，不自动认定 AI 腔；它不能判定一段话好不好笑。对照库只是审读材料，尚未建立自动模型评分或自动批量改写。
